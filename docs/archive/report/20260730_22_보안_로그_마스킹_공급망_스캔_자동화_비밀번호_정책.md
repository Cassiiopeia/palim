# [보안] 로그 마스킹 · 공급망 스캔 자동화(SBOM/CodeQL/Dependabot) · 비밀번호 정책

## 개요

`docs/09-SECURITY.md` 에서 구현 필요로 판정된 3개 항목과, 공개 저장소 전환에 필요한 방어를
구현했다. 커밋 히스토리 전수 검사 결과 리터럴 비밀값이 커밋된 적은 없어 히스토리 재작성 없이
정책 전환만으로 완료했다.

## 변경 사항

### 공개 저장소 방어

- `.gitignore`: `application-prod.yaml` 추적 제거 (`.example` 템플릿만 커밋). `docs/somansa/` 차단
- `.github/workflows/build.yml` `guard` 잡: 커밋 메시지의 AI 흔적(`Co-Authored-By`·`Generated
  with`·`noreply@anthropic.com`·🤖)과 사내 자료 추적을 **빌드 실패로 차단** — 규칙 문서만으로는
  강제되지 않는다
- `CLAUDE.md` 금지사항 9: 사내 제품명·호스트명·이슈 번호 금지. 필요 시 "레거시 관리자 시스템" 통칭
- 기존 문서·코드 주석·GitHub 이슈/PR 본문의 사내 명칭 전부 익명화
- 저장소 설정(API): secret scanning + push protection + Dependabot alerts/보안 수정 활성화

### 공급망 · 정적 분석

- `.github/dependabot.yml`: gradle·github-actions·npm 주간 스캔. 메이저 업그레이드 제외 —
  Boot 4 전환에서 겪었듯 메이저는 관례가 깨져 수동 판단이 필요하다
- `.github/workflows/codeql.yml`: PR 마다 + 주 1회 전체 스캔 (새 취약점 패턴 재검사)
- `build.gradle.kts`: CycloneDX 플러그인 — main 빌드마다 SBOM(`bom.json`) 아티팩트 90일 보관.
  취약점 공지 시 "우리가 그 버전을 쓰는가"를 빌드 재현 없이 답한다

### 로그 마스킹

- `palim-app/logging/SecretMaskingConverter` + `logback-spring.xml`: 출력 직전 비밀값 마스킹.
  `ChannelCredentialService` 경계 규칙의 로그 계층 버전 — 마지막 방어선이지 유일한 방어선이 아니다

### 비밀번호 정책

- `palim-auth/PasswordPolicy`: 최소 12자, 아이디 포함 금지, 동일 문자 4연속 금지.
  **복잡성 조합("대문자+숫자+특수문자")은 강제하지 않는다** — NIST SP 800-63B. 조합 강제는
  예측 가능한 변형만 유도하고 길이가 강도를 만든다
- `AdminAccountService.changePasswordVerified`: 현재 비밀번호 재확인 필수 — 세션만 잡은
  공격자가 비밀번호를 바꿔 발주자를 쫓아내는 것을 막는다
- `/settings/account` 화면: `autocomplete="new-password"` 지정으로 브라우저 비밀번호 관리자 연동
- 감사 기록: 성공 `PASSWORD_CHANGE` / 실패 `PASSWORD_CHANGE_FAILED` — 실패 반복은 대입 공격 신호
- `ErrorCode` A005~A008 + 한/영 메시지

### 레거시 공통 보안 모듈 전수 검토 (09-SECURITY 문서화)

| 레거시 모듈 | 판정 | 근거 |
|---|---|---|
| SQL 인젝션 필터 (파라미터 정규식 제거) | 거부 | 정상 데이터를 조용히 파괴 + 우회 가능. 방어는 전 SQL 파라미터 바인딩 |
| XSS 입력 필터 (문자 삭제) | 거부 | 입력 훼손 안티패턴. 출력 이스케이프 + CSP 가 정석 |
| 캐시 방지 필터 | 이미 충족 | Spring Security 기본 |
| 파일명 User-Agent 분기 | 현대식 대체 | `ContentDisposition` 빌더 (RFC 6266) — 엑셀 기능 시 적용 |
| `"../"` 문자열 치환 | 현대식 대체 | `Path.normalize` + 기준 디렉터리 검증 (`....//` 우회 차단) |

## 주요 구현 내용

**마스킹 패턴은 좁게.** `key` 단독 같은 넓은 패턴은 `dedupeKey`·`nextToken`(수집 커서) 같은
비밀 아닌 값까지 지운다 — 마스킹된 로그는 복원할 수 없어 장애 조사를 방해한다. 확실한 비밀
이름과 형식만 잡되, 놓치기 쉬운 엣지 두 개를 테스트로 고정했다: `Bearer` 접두사 뒤 실제 토큰,
봇 API URL 처럼 단어 경계가 없는 위치의 텔레그램 토큰.

**부트스트랩 초기 비밀번호에는 정책을 적용하지 않는다.** 환경변수 초기값이 정책 미달이라고
기동을 막으면 발주자가 시스템에 영영 못 들어간다. 화면 변경 경로에만 적용한다.

## 주의사항

- 접속 IP 제한은 애플리케이션이 아니라 Cloudflare Access 자리 — P-02(인증정보 전달) 이후 처리
- CodeQL 은 main push/PR 트리거라 기능 브랜치 push 에서는 돌지 않는다 — PR 시점에 검증된다
- Dependabot PR 중 보안 패치는 우선 머지한다. 메이저는 자동 생성되지 않으므로 분기별 수동 점검
