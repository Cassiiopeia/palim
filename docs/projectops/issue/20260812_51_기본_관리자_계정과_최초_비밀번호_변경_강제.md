## 📝 현재 상태 — 비밀번호 변경은 이미 동작한다

먼저 확인한 사실이다. **비밀번호 변경 기능은 이미 구현되어 있고 DB 에 반영된다.**

| 구성 | 위치 | 상태 |
|---|---|---|
| 변경 화면 | `/settings/account` (사이드바 「계정 설정」) | 있음 |
| 현재 비밀번호 재확인 | `AccountController.changePassword` | 있음 |
| 비밀번호 정책 | `PasswordPolicy` — 최소 12자, 아이디 포함 금지, 같은 문자 4회 연속 금지 | 있음 |
| DB 반영 | `AdminAccount.changePassword` → `admin_account.password_hash` | 있음 |
| 감사 로그 | 변경 성공·실패 모두 기록 | 있음 |

`docs/09-SECURITY.md` 에 "비밀번호 정책 + 변경 화면 — 후속(#22 잔여)"으로 적혀 있으나 **문서가
실제 구현보다 뒤처진 것**이다. 이 이슈에서 함께 바로잡는다.

## 🛠️ 그래서 실제로 해야 할 일

### 1. 기본 관리자 계정 자동 생성

현재는 계정이 없고 `ADMIN_PASSWORD` 환경변수도 없으면 **기동을 실패시킨다**
(`AdminAccountBootstrap`). 로그인할 수 없는 상태로 뜨는 것을 막으려는 의도였으나, 새 환경에
올릴 때마다 환경변수를 먼저 준비해야 해서 번거롭다.

→ **환경변수가 없으면 기본 계정(`admin` / `admin`)을 만들고 정상 기동한다.**

### 2. 최초 로그인 시 비밀번호 변경 강제 — 이것이 없으면 1번을 넣으면 안 된다

이 저장소는 PUBLIC 이고 화면은 인터넷에 노출된다. 기본 계정을 그냥 만들면 **배포 즉시 누구나
`admin/admin` 으로 들어올 수 있다.** 기본값은 공개된 것이나 마찬가지다.

→ 기본 비밀번호로 만든 계정은 **변경 전까지 다른 화면을 쓰지 못하게 한다.** 공유기·NAS 가
쓰는 방식이며, 편의와 안전을 동시에 만족하는 유일한 조합이다.

- [ ] `admin_account` 에 `password_change_required` 플래그 추가 (마이그레이션)
- [ ] 부트스트랩: 환경변수 없이 기본값으로 만든 계정은 플래그 `true`
- [ ] 인터셉터: 플래그가 `true` 면 `/settings/account`·`/logout` 외 모든 요청을 변경 화면으로 리다이렉트
- [ ] 변경 성공 시 플래그 해제
- [ ] 변경 시 **다른 세션 전부 종료** — 초기 비밀번호가 이미 노출됐을 수 있다

### 3. UX

- [ ] 강제 변경 화면 상단에 **왜 지금 바꿔야 하는지** 안내
  ("초기 비밀번호를 사용 중입니다. 이 화면은 인터넷에서 접근 가능하므로 지금 변경해야 합니다.")
- [ ] 사이드바·다른 메뉴를 **숨기지 않고 비활성**으로 둔다 — 사라지면 고장으로 오해한다
- [ ] 현재 비밀번호 입력란은 그대로 둔다(초기값을 입력). 자동 통과시키면 세션만 잡은 공격자가
      비밀번호를 바꿔 발주자를 쫓아낼 수 있다
- [ ] 정책 위반 시 **무엇이 틀렸는지** 구체적으로 (이미 `ErrorCode` 세 종이 있다)
- [ ] 변경 완료 후 대시보드로 이동하며 성공 안내

### 4. 배포 설정

- [ ] `application-prod.yaml.example` 의 `ADMIN_USERNAME`·`ADMIN_PASSWORD` 설명 보강 —
      "미지정 시 기본 계정이 생성되고 최초 로그인에서 변경이 강제된다"
- [ ] **GitHub Actions Secret 은 현재 쓸 곳이 없다** — 워크플로우가 빌드·GHCR 푸시까지만 하고
      배포 단계가 없다. 배포 워크플로우를 만들 때 함께 연결한다. 그전까지는 서버 환경변수로 주입
- [ ] 실제 계정 정보는 저장소·이슈·문서 어디에도 쓰지 않는다. `admin/admin` 은 공개된 초기값일 뿐

## 🔎 함께 검토한 사항 (별도 이슈 후보)

로그인 흐름 전반을 점검한 결과 기본기는 충실하나, **인터넷 노출 + 관리자 1계정** 전제에서 두
가지가 비어 있다. 코드가 아니라 Cloudflare 설정으로 해결하는 편이 싸다.

| 항목 | 내용 |
|---|---|
| 로그인 rate limit | 계정 잠금은 있으나 요청 빈도 제한이 없다. 계정이 1개라 아이디가 사실상 공개이므로 **10분마다 5회만 틀려주면 관리자가 영구히 못 들어온다**(잠금 DoS). bcrypt 는 의도적으로 느려 인증 자체가 CPU 소모 벡터이기도 하다. Cloudflare WAF Rate Limiting 으로 `POST /login` 제한 |
| 2단계 인증 | 비밀번호 하나로 재고 조작·API 키 교체가 가능하다. Cloudflare Access 를 앞에 두면 앱 수정 없이 이메일 OTP 를 붙이고 로그인 화면 자체를 인터넷에서 가릴 수 있다 |
