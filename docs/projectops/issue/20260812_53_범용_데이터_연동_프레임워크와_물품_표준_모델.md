## 📝 왜 필요한가

외부 시스템 데이터를 우리 안으로 들여오는 일이 앞으로 계속 생긴다. 그런데 원천은 회사마다·
시스템마다 다르다. 엑셀로 주기도, JSON으로 주기도, API로 주기도 한다.

원천마다 Java 코드를 새로 쓰면 세 가지가 따라온다.

- 새 발주사·새 원천이 붙을 때마다 배포가 필요하다
- 원천 양식이 바뀌면 코드를 고쳐야 한다
- 도메인 로직과 파싱 코드가 뒤엉켜 어느 쪽도 손대기 어려워진다

**연동 정의를 데이터로 두면 셋 다 사라진다.** 새 원천은 화면에서 커넥터를 하나 더 만드는
일이 되고, 양식 변경은 매핑 버전을 올리는 일이 된다.

재고 정합성 대사(#49)를 첫 구현체로 삼되, **연동 엔진 자체는 도메인을 모르게** 만든다.

## 🛠️ 작업 상세 내용

### 1. 새 모듈 `palim-connector`

범용 연동 엔진. 도메인을 모른다. `palim-automation` 이 이 위에 얹힌다.

- [ ] `settings.gradle.kts` 에 모듈 추가, `palim-common` 만 의존
- [ ] `palim-automation` → `palim-connector` 의존 추가

`palim-automation` 안에 두면 나중에 다른 도메인이 붙을 때 재고 코드에 의존이 생긴다.

### 2. 연동 정의 계층 (마이그레이션 V15)

- [ ] `target_model` — 목표 모델. `kind`(BUILTIN/CUSTOM) · `storage`(TABLE/JSONB) · `natural_key_fields`
- [ ] `target_field` — 필드 정의. 키 · 표시명 · 타입 · 필수 · 기본값 · 순서
- [ ] `connector` — 연동 하나. 원천 유형 · 접속 정보 참조 · cron · 증분 커서
- [ ] `connector_mapping` — **매핑 버전**. DRAFT/ACTIVE/ARCHIVED · 원천 스키마 스냅샷
- [ ] `connector_field_map` — 필드 연결 + 변환 규칙
- [ ] `unit_conversion` — 단위 환산 규칙 (품목별/전역)
- [ ] 전 테이블에 `tenant_id`. 지금은 기본 테넌트 하나로 운영하되 **나중에 넣으면 재작성**이다

### 3. 실행 계층

- [ ] `connector_run` — `run_mode`(TEST/LIVE) · 트리거 · **사용한 매핑 버전** · 건수
- [ ] `connector_run_error` — 실패 행을 **원본째로** 보존
- [ ] `custom_record` — 커스텀 모델 데이터 (JSONB + GIN)

### 4. 기본 제공 물품 표준 모델

물품이면 무엇이든 담기도록 성격이 다른 셋으로 나눈다. 빈 칸을 허용해 업종을 가리지 않는다.

- [ ] `item` — 품목 마스터 (식별·분류·공급·단위·금액·상태)
- [ ] `stock_snapshot` — 시점별 재고 (기준시각·위치·로트·수량·금액)
- [ ] `stock_movement` — 입출고 이력 (구분·수량·위치·전표)
- [ ] `outbound_order` — 출고 주문. **이 모델만 개인정보를 담는다**(수령자 정보). 보존기간·
      마스킹·접근권한을 여기에만 걸 수 있도록 분리
- [ ] 전 모델에 `attributes` JSONB 확장 슬롯 — 표준에 없는 컬럼을 버리지 않는다

처음에는 필요 없어 보이던 컬럼이 나중에 필요해지는 일이 반복된다. 버렸다면 원천에서 다시
받아야 하는데 **과거 시점 데이터는 다시 받을 수 없다.**

### 5. 저장 방식 — 하이브리드

- [ ] 기본 제공 모델은 정식 테이블, 커스텀 모델은 `custom_record` JSONB
- [ ] 둘 다 같은 파이프라인을 타고 **저장 직전에만 갈라진다**
- [ ] **런타임 DDL 금지** — 스키마 변경은 전부 Flyway. 앱 계정에 DDL 권한을 주지 않는다

동적 DDL은 마이그레이션과 충돌하고, 실패 시 롤백 경로가 없다.

### 6. 단위 환산

- [ ] 수량은 원본(`quantity`/`unit`)과 환산값(`base_quantity`/`base_unit`)을 **둘 다** 저장
- [ ] 품목별 규칙 → 전역 규칙 순으로 조회
- [ ] **규칙이 없으면 1:1로 넘기지 않고 실패시킨다**

조용히 통과시키면 BOX 12개가 EA 12개로 둔갑하고, 그 오류는 대사 결과가 이상해질 때까지
아무도 모른다.

### 7. 증분 수집과 자연키

- [ ] `incremental_mode`(FULL/INCREMENTAL) · `cursor_field` · `cursor_value`
- [ ] **성공한 실행만 커서를 전진**시킨다
- [ ] 적재는 INSERT 가 아니라 자연키 기반 **UPSERT**

재시도가 안전해야 자동화가 안심되고, 안심돼야 사람이 실제로 자동화를 켠다.

### 8. 온보딩 흐름 (8단계)

- [ ] 연동 만들기 → 원천 붙이기 → (선택) AI 분석 → 관리자 확인 → **테스트 연동** →
      후처리 설정 → 확정·cron 등록 → 운영
- [ ] 각 단계에서 중단·재개 가능 (매핑 `DRAFT` 보존)

### 9. AI 는 보조, 수동이 1급

- [ ] **AI 버튼을 한 번도 안 눌러도 전 과정이 완주된다**
- [ ] 헤더에서 필드 목록 추출은 코드가 한다. AI 는 매핑 초안만 제안
- [ ] AI 출력은 **구조화 출력(json_schema)** 으로 받아 코드가 검증
- [ ] **매일 도는 실행에는 AI 가 개입하지 않는다** — 비용 0, 같은 입력에 같은 결과

### 10. 후처리

- [ ] 선언적 규칙 (값 변환·필터·파생 컬럼·기본값) — 화면에서 선택
- [ ] py 훅 — 규칙으로 안 되는 커스텀. `04-CONVENTIONS` py 규약 준수
- [ ] **SQL 직접 실행은 넣지 않는다** — 공개 저장소이고 한 번 뚫리면 DB 전체가 열린다

py 훅은 DB 에 직접 손대지 않는다. 데이터를 받아 가공된 데이터를 돌려줄 뿐이라 잘못 짜도
테이블이 날아가지 않는다.

### 11. 안정성 장치

- [ ] **스키마 드리프트 감지** — 원천 필드가 스냅샷과 다르면 적재하지 않고 중단 + 알림
- [ ] **부분 실패 허용** — 성공분은 적재, 실패 행만 원본째 보존
- [ ] **실행 단위 롤백** — `run_id` 로 한 실행분만 정확히 삭제
- [ ] **동시 실행 차단** — 커넥터 단위 락 (cron 과 수동 실행이 겹치는 순간은 반드시 온다)
- [ ] **비밀값 분리** — API 키는 기존 암호화 저장 재사용, `connector` 에는 참조만

최악의 실패는 *원천 양식이 바뀌었는데 조용히 잘못된 데이터가 들어가는 것*이다.

### 12. 화면

- [ ] 커넥터 목록 · 만들기 위저드 · 매핑 편집기 · 미리보기 · 테스트 실행 결과 ·
      실행 이력 · 목표 모델 관리 · 단위 환산 규칙

### 13. 예외

- [ ] `ErrorCode` 추가 — `CONNECTOR_NOT_FOUND` · `CONNECTOR_ALREADY_RUNNING` ·
      `CONNECTOR_SOURCE_UNREACHABLE` · `MAPPING_NOT_ACTIVE` · `SCHEMA_DRIFT_DETECTED` ·
      `REQUIRED_FIELD_MISSING` · `FIELD_TYPE_MISMATCH` · `UNIT_CONVERSION_NOT_FOUND` ·
      `HOOK_EXECUTION_FAILED` · `HOOK_TIMEOUT` · `TARGET_MODEL_IN_USE`
- [ ] `errors.properties` / `errors_en.properties` 각 한 줄씩
- [ ] 새 예외 클래스는 만들지 않는다

### 14. 테스트

- [ ] 단위 — 변환 규칙 엔진 · 단위 환산(규칙 없을 때 실패하는지) · 자연키 · 드리프트 감지
- [ ] 통합(Testcontainers) — **롤백이 정확히 그만큼만 지우는지**, **증분 재실행에 중복이
      없는지**

이 둘이 깨지면 사람이 시스템을 믿지 못하고, 믿지 못하면 쓰지 않는다.
