## 📝 왜 필요한가

#53 에서 연동 엔진(Phase 1)을 만들었다. 엑셀을 올리면 매핑대로 변환되어 표준 모델에 적재되는
파이프라인은 완성됐고 테스트 362건이 이를 보장한다.

**그런데 화면이 없어 사람이 쓸 수 없다.** 커넥터를 만들 방법도, 매핑을 정의할 방법도 없다.
연동 정의를 데이터로 둔 이유가 "화면에서 만들기 위해서"였으므로, 화면이 없으면 그 설계가
의미를 갖지 못한다.

이 이슈는 **Phase 2 — 사람이 연동을 만들고 돌릴 수 있게 하는 화면**이다.

## 🛠️ 작업 상세 내용

### 1. 커넥터 목록 (`/connectors`)

- [ ] 이름 · 목표 모델 · 원천 유형 · 활성 여부 · 마지막 실행 결과 · 성공률
- [ ] 실패한 커넥터가 눈에 띄어야 한다 — 목록을 훑을 때 문제를 먼저 보게 한다
- [ ] 새 연동 만들기 버튼

### 2. 커넥터 만들기

- [ ] 이름 · 코드 · 목표 모델 선택 · 원천 유형 · 기준 단위
- [ ] 목표 모델은 등록된 것에서 고른다(기본 제공 4종 + 커스텀)

### 3. 매핑 편집기 — 이 이슈의 핵심

- [ ] 파일 업로드 → 헤더 추출 → **왼쪽 원천 필드 / 오른쪽 목표 필드**
- [ ] 사람이 좌우를 연결한다. 필수 목표 필드는 표시로 구분
- [ ] 변환 규칙 선택(값 변환 · 코드 치환 · 기본값 · 날짜 형식)
- [ ] **AI 초안 채우기 버튼은 이번 범위가 아니다.** 수동만으로 완주되어야 한다(설계 원칙)

### 4. 미리보기

- [ ] 원본 5행 → 변환 결과 5행을 나란히
- [ ] 실패 행은 사유와 함께 표시 — 확정 전에 무엇이 깨지는지 보여준다

### 5. 테스트 실행과 확정

- [ ] `TEST` 실행 → 성공 N · 실패 M · 사유별 묶음
- [ ] 실패 행의 원본을 화면에서 확인
- [ ] 스테이징 비우기
- [ ] 문제없으면 **매핑 확정(ACTIVE)** → 이후 LIVE 실행 가능

### 6. 실행 이력 (`/connectors/{id}/runs`)

- [ ] 실행별 건수 · 소요 · **사용한 매핑 버전** · 트리거
- [ ] 실패 행 원본 조회 (**페이징 필수** — 무제한 List 는 대량 실패 시 힙을 채운다)
- [ ] 되돌리기 버튼 (LIVE 는 최근 1회만 활성)

### 7. 목표 모델 관리 (`/connectors/models`)

- [ ] 기본 제공 모델과 필드 조회
- [ ] 커스텀 모델 정의 · 필드 추가

### 8. 단위 환산 규칙 (`/connectors/units`)

- [ ] 전역/품목별 환산 등록·수정
- [ ] 이 화면이 없으면 단위가 섞인 원천에서 적재가 막힌 채 풀 방법이 없다

### 9. 멀티테넌시 필터 적용

- [ ] Hibernate `@FilterDef`/`@Filter` 를 표준 모델·연동 엔티티에 적용
- [ ] 세션 시작 시 현재 테넌트로 필터 활성화 — **인터셉터 한 곳에서만** 한다
- [ ] `JdbcClient` read model 은 필터가 안 걸리므로 테넌트 조건 강제 헬퍼

Phase 1 에서 컬럼과 인덱스만 넣고 미룬 작업이다. 화면이 있어야 세션 컨텍스트가 생긴다.
