## 📝 규칙을 고칠 수는 있는데 무엇이 나아졌는지 알 수가 없다

이름 다듬기 규칙 화면에서 규칙을 넣고, 고치고, 순서를 바꿀 수 있다. 그런데 **그렇게 해서 무엇이
나아졌는지 이 화면은 말해 주지 않는다.** 보여주는 것은 규칙의 이름과 정규식뿐이고, 결과는 다음
화면에서 「이을 수 있는 것이 줄었다」 로만 드러난다. 어느 규칙 때문인지는 어디에도 안 나온다.

규칙을 고치는 목적은 하나다 — **짝이 되는 품목을 늘리는 것.** 그 숫자가 화면에 없다.

### 손이 많이 가는 것들

| 지금 | 무엇이 문제인가 |
|---|---|
| 순서를 `↑` `↓` 로 한 칸씩 옮긴다 | 규칙이 다섯이면 「맨 아래를 맨 위로」 에 네 번을 눌러야 하고, 누를 때마다 화면이 새로 그려져 어디까지 옮겼는지 놓친다 |
| 켜고 끄기가 「끄기」/「켜기」 로 글자가 바뀌는 버튼 | 글자를 읽어야 지금이 어느 쪽인지 안다 |
| 미리보기가 **새 규칙을 만들 때만** 나온다 | 이미 들어 있는 규칙들이 무슨 일을 하고 있는지는 볼 수가 없다 |
| 규칙이 전역이다 | 원천마다 표기 습관이 다른데 한쪽에만 걸 방법이 없다 |

### 원천별로 걸어야 하는 실제 이유

한쪽은 이름 끝에 밑줄과 유통기한을 붙이고, 다른 쪽은 아무것도 붙이지 않는다.

```
전산   제품B 70g_26.12.12
물류   제품B
```

밑줄 규칙을 양쪽에 걸면 지금은 무해해도, 밑줄을 다른 뜻으로 쓰는 원천이 하나 붙는 순간 조용히
망가진다. 그때 드러나는 증상은 「이을 수 있는 것이 줄었다」 뿐이다.

### 그리고 위험한 것 하나

기본 규칙 「괄호와 그 안의 내용을 뺀다」 가 켜진 채로 들어 있다. 그런데 실제 자료에는
**유통기한으로만 구분되는 품목**이 있다.

```
제품C 850g (27.03.16)
제품C 850g (27.04.16)
제품C 850g (27.04.20)
```

괄호를 떼면 셋이 한 이름이 된다. 그러면 대조는 「재고가 맞는다」 고 말하는데 실제로는 서로 다른
세 품목이 합쳐진 것이다 — **불일치를 못 찾는 것보다 나쁘다. 틀렸다는 사실조차 드러나지 않는다.**

지금은 이런 일이 벌어져도 화면이 아무 말도 하지 않는다.

## ✅ 고칠 것

- [ ] **성적표** — 「짝이 되는 품목 N → M」. 규칙을 하나도 걸지 않았을 때와 견준 값이라야
      규칙이 한 일이 드러난다
- [ ] **규칙마다 걸린 수** — 이 자료에서 몇 개를 바꿨나. 아무 데도 안 걸리는 규칙은 값 없음으로
      표시해 쌓여만 있는 규칙을 찾아낼 수 있게
- [ ] **충돌 경고** — 서로 다른 품목이 다듬은 뒤 같은 이름이 되면 어느 것들인지 보여준다
- [ ] **끌어서 순서 바꾸기** — 놓는 순간 저장한다. 따로 「저장」 을 누르게 하면 옮겨 놓고 안 누른
      채 떠나는 일이 생긴다
- [ ] **토글 스위치** — 글자를 읽지 않아도 켜짐/꺼짐이 보이게
- [ ] **규칙을 걸 원천 고르기** — 모든 원천 / 특정 원천
- [ ] **자주 쓰는 정규식** — 누르면 입력칸이 채워진다. 고를 수 있는 목록이 아니라 백지에서
      시작하지 않게 해 주는 출발점이다
- [ ] 스크립트가 막히거나 실패해도 순서를 바꿀 길을 남긴다 (키보드만 쓰는 사람도 마찬가지)

## 하지 않을 것

- **정규식 입력을 없애지 않는다.** 어떤 품목명 체계가 올지 미리 알 수 없다. 체크박스로 가두면
  그 목록에 없는 표기 습관을 가진 곳에서는 이 프로그램을 쓸 수 없게 된다. 프리셋은 정규식을
  대신하는 것이 아니라 처음 한 줄을 채워 주는 것이다
