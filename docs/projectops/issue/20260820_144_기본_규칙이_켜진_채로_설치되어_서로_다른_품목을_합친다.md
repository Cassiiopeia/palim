## 📝 기본 규칙이 켜진 채로 설치되어 서로 다른 품목을 합친다

설치하면 이름 다듬기 규칙 네 개가 **켜진 채로** 들어간다. 그중 둘이 위험하다.

- 「괄호와 그 안의 내용을 뺀다」
- 「이름에 박힌 날짜를 뺀다」

품목명에 소비기한이 붙어 오는 곳에서는 편하다. 그런데 **소비기한으로만 구분되는 서로 다른
품목**이 있는 곳에서는 그것들을 한 물건으로 만든다.

```
제품A 850g (27.03.16)
제품A 850g (27.04.16)   →  전부 「제품A850g」
제품A 850g (27.04.20)
```

그러면 대조는 「재고가 맞는다」 고 말하는데 실제로는 셋이 합쳐진 것이다.
**불일치를 못 찾는 것보다 나쁘다 — 틀렸다는 사실조차 드러나지 않는다.**

발주사 확인 결과 **소비기한별로 별도 품목**으로 관리한다(입고 시점마다 기한이 다르기 때문).
즉 이 기본 규칙은 그 회사에서 틀렸고, 같은 방식으로 관리하는 곳이라면 어디서든 틀린다.

### 왜 «기본값» 이라서 더 위험한가

「시스템이 알아서 켜 둔 것」 은 사람이 의심하지 않는다. 자기가 넣은 규칙이면 결과가 이상할 때
그 규칙을 떠올리지만, 처음부터 있던 것은 **존재 자체를 모른다.** 그래서 원인을 자기 자료에서
찾게 되고, 찾지 못한다.

### 지금 끄려면

규칙을 하나씩 꺼야 한다. 넷이면 네 번, 나중에 스물이면 스무 번이다.

## ✅ 고칠 것

- [ ] 기본 규칙을 **꺼진 상태로** 되돌린다. 지우지는 않는다 — 소비기한을 이름에 붙이지 않는
      곳에서는 유용하므로, 필요하면 화면에서 켠다
- [ ] **「모두 끄기」** 를 넣는다. 껐다 켜 보며 짝 개수가 어떻게 변하는지 보는 것이 이 화면에서
      제일 자주 하는 일이다
- [ ] 켤 때 무엇이 합쳐지는지 보이게 한다 (충돌 경고는 이미 있다)
