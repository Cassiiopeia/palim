# 인플루언서 등급표 · 라이징 레이더 — 설계 스펙

> 2026-08-11 브레인스토밍 확정. `docs/01-REQUIREMENTS.md` 마케팅 모듈
> 「인플루언서 등급표」의 상세 설계. `palim-automation` 모듈 1호 구현이다.

## 1. 목적

발주사가 유튜브 인플루언서 광고를 집행할 때의 핵심 문제를 푼다:

- **광고 단가는 구독자 수를 따라가지만, 실제 성과는 조회수·반응으로 나온다.** 이 괴리를
  정량화해 "단가 대비 도달"이 좋은 채널을 찾는다.
- **구독자는 조회수보다 늦게 붙는다.** 조회수가 먼저 터지고 구독자·단가가 따라오는
  시차(차익 구간)에 있는 채널을 남보다 먼저 감지한다.
- 최종 광고 제안 판단은 **사람(내부 심사)** 이 한다. 시스템은 근거를 갖춘 후보와
  점수를 제공할 뿐, 자동으로 탈락시키거나 발송하지 않는다.

## 2. 범위

### 1차 구현 (이 스펙)

- 유튜브 파이프라인 전체: 발굴 → 확장 → 선별 → 수집 → 분류 → 스코어링 → 심층 심사
- 트랙 1 **등급표**(캠페인 기준 점수) + 트랙 2 **라이징 레이더**(선점 감지)
- 트렌드 보드(주간 키워드 빈도 비교) + 텔레그램 주간 알림
- 웹 심사 화면(제안/보류/제외)
- `palim-automation` 모듈 골격 + `scripts/` 규약 구현(이 모듈이 1호)

### 범위 밖 (후속 사이클)

| 항목 | 사유 |
|---|---|
| 인스타 교차 매핑 (Business Discovery) | Meta 앱 심사·비즈니스 계정 연결 선행 필요 |
| DM 초안 생성 | 등급표 루브릭 안정화 후 |
| 쇼츠 전용 인플루언서 평가 | 롱폼 루브릭과 별개 기준 필요 — 쇼츠 지표는 저장만 |
| 외부 웹 검색 자동화(평판 조회) | 동명이인 오탐 多 — 심사 화면의 검색 바로가기로 대체 |
| 트렌드 AI 클러스터링 | 1차는 단순 빈도 비교까지 |

## 3. 데이터 소스와 정책 경계

### 공식 API (YouTube Data API v3)

| 데이터 | 엔드포인트 | unit |
|---|---|---|
| 채널 통계 (50개 배치) | `channels.list` | 1 |
| 영상 통계·duration·유료광고표시 (50개 배치) | `videos.list` | 1 |
| 인기 차트 (KR × 카테고리) | `videos.list chart=mostPopular` | 1 |
| 키워드 검색 | `search.list` | **100** |
| 채널 추천 섹션 | `channelSections.list` | 1 |
| 최근 업로드 목록 | `playlistItems.list` | 1 |
| 댓글 (time / relevance 정렬) | `commentThreads.list` | 1 |

일일 무료 한도 10,000 units. 일일 예상 소모 ≈ 5,500 (검색 2,000 + 수집 ~1,400 +
차트 60 + 확장·댓글 등). `api_quota_ledger` 로 기록하고 예산 초과 시 배치가 커서를
저장하고 스스로 멈춘다.

### 비공식 경로 — 자막 (명세 §제외 4의 예외, 격리 조건부)

- 남의 채널 자막은 공식 API 로 받을 수 없다(`captions.download` 는 소유자 인증 필수).
- yt-dlp 로 공개 자동자막을 수집하되 **`TranscriptProvider` 어댑터로 격리**한다.
  실패·차단 시 `transcript.status=BLOCKED` 기록 후 **메타+댓글만으로 심사를 계속**한다.
  3회 연속 차단 시 텔레그램 경고. 이 판단은 `docs/07-DECISIONS.md` 에 기록한다.
- 영상 파일 다운로드·STT 는 하지 않는다.

### 개인정보 경계

- 댓글은 **텍스트 + 좋아요 수 + 정렬 출처만** 저장. 작성자 핸들·프로필은 수집 즉시 폐기.
- AI 전송 전 본문 내 핸들 패턴(`@...`)을 마스킹한다.
- 저장소는 PUBLIC — 코드·문서·테스트에 실존 채널명·발주사 정보를 넣지 않는다.
  캠페인 내용·캘리브레이션 정답셋은 DB 에만 존재한다.

## 4. 파이프라인 (야간 배치, 재개 가능 커서)

| 단계 | 내용 | 비고 |
|---|---|---|
| ① 발굴 | **1순위 키워드 검색**(카테고리별 시드 키워드 YAML, 일 20회) · 2순위 수동 시드 엑셀 업로드 · 3순위 KR 인기 차트 누적 | 중견(구독 5만~50만) 채널은 검색이 주력. 차트는 급상승 감지 보조 |
| ② 확장 | 발견 채널의 추천 채널 섹션을 2홉까지 순회 | 커버리지 한계 인정(큐레이션 안 하는 채널 多) |
| ③ 선별 | `country=KR` 또는 제목·설명 한글 비율 임계 + 구독자 하한 | quota 0 |
| ④ 수집 | 채널 통계 → 최근 롱폼 50개 목록 → 영상 통계 배치 | 티어별 갱신: HOT 주1 · WARM 격주 · COLD 월1 · 라이징 매일 |
| ⑤ 분류 | AI 가 채널 설명 + 최근 제목 20개로 자체 카테고리 다중 라벨 | 유튜브 원본 카테고리도 병행 저장 |
| ⑥ 룰 점수 | 70점 산출 + 배지 + 라이징 스캔 | 순수 함수, quota 0 |
| ⑦ 심층 심사 | **수동 트리거** — 캠페인 상위 N명만 자막 + 댓글 수집 → AI 30점 | 비용·차단 리스크 단계는 사람이 명시적으로 실행 |

## 5. 스코어링 루브릭

### 공통 규칙

- 대상은 **롱폼만** (duration ≤ 60초는 쇼츠로 분리, 지표 보관만).
- 집계는 전부 **중앙값**. 참여율 계산에서 댓글 3배 가중.
- 임계값·배점은 전부 `influencer-scoring.yml` — 발주사와 합의한 루브릭 문서가 원본이며
  변경 시 문서 먼저 갱신(01-REQUIREMENTS 인수 방식).
- 구독자 구간별(1~5만 / 5~20만 / 20~100만 / 100만+) 임계표 구조를 YAML 에 처음부터
  두되, 1차 출시는 단일 임계표로 시작한다.

### 하드 탈락 (점수 계산 전)

마지막 업로드 90일 초과 · 롱폼 5개 미만 · 캠페인 구독자 하한 미달 · 수동 제외 목록.
(AI 는 탈락 권한이 없다 — 플래그만.)

### 룰 점수 70점

| 항목 | 배점 | 계산 |
|---|---|---|
| 실도달량 | 14 | 롱폼 조회수 중앙값을 **캠페인 목표 도달 구간 대비** 로그 스케일 채점 |
| 도달 효율 VSR | 14 | 조회수 중앙값 ÷ 구독자. 0.5↑=만점 ~ 0.08↓=0 |
| 모멘텀 | 14 | 추세 6(최근10÷직전10) + 피크 대비 5(최근5÷연속5중앙값 최대) + 급락 감지 3(최근5÷직전6~20 < 0.5 → 0점+🔻배지) |
| 참여율 | 12 | (좋아요+댓글×3)÷조회수 중앙값. 8%↑=만점 ~ 1.5%↓=0 |
| 활동성 | 8 | 90일 업로드 수(주1=만점) + 마지막 업로드 경과일 |
| 안정성 | 8 | IQR÷중앙값. 0.4↓=만점 ~ 1.5↑=0 |

관측 창: 최근 롱폼 50개. 구독자 수는 직접 점수 0 — 분모로만 쓴다.
(조회수 계열 42/70 = 60%가 의도된 무게다.)

### AI 점수 30점 (심층 심사 시에만, 구조화 출력)

| 항목 | 배점 | 판정 재료 |
|---|---|---|
| 브랜드 안전성 | 12 | §6 신호 6종. **플래그+근거 인용** 방식 — 감점하되 자동 탈락 없음 |
| 캠페인 적합도 | 10 | 자막(가능 시)+메타 ↔ 캠페인 브리프 대조 |
| 시청자 반응 품질 | 8 | 댓글 진정성·구매 의향 빈도 vs 봇·무의미 비율 |

- 출력 스키마에 `evidence`(원문 인용) 배열 필수 — 비어 있으면 해당 항목 무효(중립값), 재시도 1회.
- **입력 해시 캐시**: 영상 목록·댓글이 안 바뀌면 재호출 없이 기존 점수 유지(재현성).

### 등급

S 85+ / A 70~84 / B 55~69 / C 40~54 / D 40 미만.

### 점수 밖 표시 항목 — 추정 CPV

`추정 단가 = 구독자 × 카테고리별 단가계수(YAML)` / `추정 CPV = 추정 단가 ÷ 조회수 중앙값`.
업계 관행 추정치라 점수에 섞지 않고 별도 컬럼. 등급표는 **총점순 / CPV 효율순** 두 정렬 제공.
실제 견적 입수 시 그 값으로 덮어쓴다.

## 6. 브랜드 안전성 판정

나무위키 등 외부 위키·커뮤니티는 쓰지 않는다(신뢰도·명예훼손 리스크·§제외 4).
공식 API 1차 자료만 쓴다. 채널당 최근 롱폼 5개 × 댓글 2세트(최신순 50 + 인기순 50).

| 신호 | 탐지 | 강도 |
|---|---|---|
| 영상 무관 비난 밀집 | AI: 최신 댓글 주제 ↔ 영상 주제 괴리도 | 최강 (논란 실시간 지표) |
| 사과·해명 영상 | 룰: 제목·설명 키워드(사과/입장/해명/죄송…) | 강 |
| 댓글 차단 | commentCount 부재/403 | 강 |
| 활동 공백 후 복귀 | 60일+ 공백 패턴 | 중 |
| 자막 내 위험 발언 | 과장 광고·정치·자극 표현 | 중 |
| 광고 남발 | 유료광고 표시 비율 50%↑ | 약 |

심사 화면에 플래그 + 원문 인용 5건 + 구글 검색 바로가기. **확정은 사람.**

## 7. 라이징 레이더 (트랙 2)

캠페인과 무관하게 전체 풀을 매일 스캔. 지수 100점:

| 신호 | 배점 | 기준 |
|---|---|---|
| VSR 과열 | 30 | 조회수 중앙값 ≥ 구독자 × 1.5 (알고리즘 외부 확산 중) |
| 가속도 | 25 | 최근 5편 중앙값 ÷ 직전 15편 ≥ 2.0 |
| 조회 속도 | 20 | 일수당 조회수가 채널 자기 기준선 대비 배율 |
| 참여 폭발 | 15 | 최근 댓글율이 채널 평균 2배↑ |
| 미개척 | 10 | 유료광고 이력 0~5% + 구독자 10만 미만 |

- **차익배율** = 조회수 중앙값 ÷ (구독자 기반 기대조회수) — 화면 최상단 표기.
- 라이징 플래그 채널은 **매일 스냅샷**. 성장 꺾이면 자동 해제.
- 주간 텔레그램 알림 "신규 라이징 N명" (`palim-notification` 경유 — 직접 봇 호출 금지).

## 8. 트렌드 보드

수집 코퍼스(차트+검색+신규 영상 제목·태그)의 주간 단어 빈도를 전주와 비교 →
카테고리별 뜨는 키워드 Top 10. 뜨는 키워드는 **발굴 시드로 자동 환류**된다
(트렌드 → 검색 → 그 분야 라이징 발굴 루프). 채널 최근 영상이 뜨는 키워드와 겹치면
등급표에 "트렌드 탑승" 배지.

## 9. 데이터 모델 (Flyway, 전부 timestamptz)

`channel`(마스터·티어·상태) · `channel_category`(원본+AI 다중 라벨) · `video`(is_short,
has_paid_promotion 포함) · `channel_snapshot`(일별) · `campaign`(브리프) ·
`score`(룰 세부 jsonb + AI 세부 jsonb + 배지 + input_hash — 총점·등급만 컬럼) ·
`rising_signal` · `review`(제안/보류/제외 + 심사자, palim-audit 연동) ·
`comment`(작성자 無) · `transcript`(status 포함) · `discovery_cursor` ·
`api_quota_ledger` · `trend_keyword`.

jsonb 채택 사유: 배점 구조가 캘리브레이션 중 계속 바뀌므로 컬럼 고정을 피한다.

## 10. 모듈 배치·실행 흐름

- `palim-automation`(신설): influencer 패키지 — 발굴·수집·분류·스코어링·심사 로직.
  YouTube API 는 Java `RestClient` 직접 호출.
- `scripts/youtube_transcript.py`(신설): yt-dlp 자막 추출만. py 규약(인자 배열·stdout
  JSON·UTF-8·타임아웃+destroyForcibly·스레드풀 2) 준수.
- `palim-web`(확장): 등급표 / 채널 상세(점수 분해+심사 버튼) / 라이징 레이더 /
  트렌드 보드 / 캠페인 관리 5개 화면. Thymeleaf + daisyUI.
- 스케줄: 매일 03:00 배치(①~⑥) · 심층 심사는 화면 수동 트리거 · 일요일 트렌드 집계+알림.

## 11. 에러 처리

- 새 예외 클래스 없음 — `ErrorCode` 추가: `YOUTUBE_QUOTA_EXCEEDED` ·
  `YOUTUBE_API_ERROR` · `TRANSCRIPT_UNAVAILABLE` · `CHANNEL_NOT_FOUND` 등 +
  `errors*.properties` 각 한 줄.
- quota 403 → 커서 저장 후 **정상 종료**(실패 아님), 다음 실행 재개.
- 자막 차단 → BLOCKED 기록 → 메타+댓글 폴백으로 심사 계속(프롬프트에 "자막 없음" 명시).
- AI evidence 누락 → 항목 무효(중립값) + 재시도 1회.

## 12. 테스트

- 점수 계산은 **순수 함수** — 합성 fixture 로 배점 전 구간 단위 테스트(쇼츠 분리·중앙값·
  급락·구간 임계 포함).
- YouTube 클라이언트는 인터페이스 격리, 통합 테스트는 Testcontainers PostgreSQL.
- fixture 에 실존 채널·발주사 정보 금지 — 전부 합성.

## 13. 캘리브레이션 (착수 조건)

임계값은 실측 감각 기반 초기값이다. 구현 직후 발주사가 아는 채널 15~20개
정답셋(DB 저장)과 시스템 순위를 대조 → YAML 조정 → 이 대조표가 합의 루브릭 문서 v1.
**루브릭 합의 전에는 등급을 대외 산출물로 쓰지 않는다.**

## 14. 미해결·후속

- YouTube API 키 발급·quota 상향 신청 주체 (발주사 계정 권장)
- 자체 카테고리 목록 초안 → 발주사 합의
