# 인플루언서 등급표 — 남은 작업과 재개 지침

> 다시 돌아와 이어 작업할 때 **왜 이렇게 남겼는지**를 먼저 읽고 시작한다.
> 설계 원본은 같은 폴더의 `2026-08-11-influencer-grading-design.md` 와
> `2026-08-11-influencer-ai-review-standard.md`.
>
> 최종 갱신 2026-08-12 (#41 · #43 · #45 머지 반영)

## 지금 상태 한 줄

**발굴부터 AI 심사, 라이징 감지, 트렌드 환류까지 루프가 완성됐다.** 모든 기준값은
DB(`SystemConfig`)에 있어 재기동 없이 화면에서 바뀐다. 남은 것은 **캘리브레이션**과
외부 연동(인스타)이다.

### 자동으로 도는 것

```
매일 03:00  발굴(검색·차트·추천) → 티어별 지표 갱신 → 캠페인 채점 → 라이징 감지
월요일 04:00 지난 주 트렌드 집계 → 급상승 키워드를 발굴 시드로 환류
월요일 09:00 이번 주 신규 라이징 텔레그램 알림
```

### 사람이 누르는 것

- AI 심층 심사(비용·자막 차단 리스크 때문에 수동)
- 캠페인 생성·채점 실행·수동 시드 등록
- 심사 판정(제안·보류·제외)과 실제 견적 입력

## 재개 전 반드시 알아야 할 것

| 항목 | 내용 |
|---|---|
| 기준값의 원본 | 코드가 아니라 **DB** 다. `ConfigDefinition` 은 최초 1회 기본값일 뿐이고 배포는 기존 값을 덮어쓰지 않는다 |
| 설정을 읽는 시점 | **빈 생성자·`@PostConstruct` 에서 읽으면 기동이 깨진다.** 부트스트랩이 빈 생성 뒤에 돌기 때문 — 첫 사용 시점으로 미룬다(`ConfigReader` javadoc) |
| 조회 결과를 화면까지 들고 갈 때 | 연관을 `@EntityGraph` 로 함께 가져와야 한다. 트랜잭션이 끝난 뒤 지연 로딩하면 화면이 500 이 난다 (#43 에서 실제로 겪었다) |
| 점수 재현성 | `influencer_score.input_hash` 가 같으면 AI 를 다시 부르지 않는다. 프롬프트·루브릭 버전도 해시에 들어간다 |
| 자막 | 공식 API 로는 남의 영상 자막을 못 받는다. yt-dlp 경로는 **언제든 깨지는 전제**이며 실패는 정상 분기다 |
| 비용 | YouTube 는 무료(할당량만), **OpenAI 만 과금**. 쿨다운·일일 상한 두 층으로 막혀 있다 |
| 새 알림 종류 추가 | `NotificationType` 에 넣으면 메시지 팩토리와 전수 검증 테스트가 컴파일 에러로 누락을 잡는다. 의도된 안전장치다 |

## 1. 캘리브레이션 — 여전히 최우선

**루브릭 초기값은 검증된 값이 아니다.** 국내 유튜브 실측 감각에 기반한 출발점일 뿐이며,
이 상태로 등급을 대외 산출물로 쓰면 안 된다(설계 스펙 §13).

### 절차

1. 발주사가 "이 사람은 좋다 / 아니다"라고 아는 채널 **15~20개**를 수동 시드로 등록
   (캠페인 관리 화면 → 채널 직접 추가)
2. 캠페인을 만들고 채점 실행
3. 시스템 순위와 발주사 직관을 대조
4. 어긋나면 설정 화면에서 가중치 조정 → 재채점 → 다시 대조
5. 합의된 값이 **루브릭 문서 v1** 이 되고 `influencer.scoring.rubricVersion` 을 올린다

### 함께 만들면 좋은 것

- **정답셋 테이블** — 채널별 발주사 평가(상/중/하)를 저장하고 시스템 순위와 나란히 보여주는
  화면. `channel_review` 가 일부 역할을 하지만 캠페인에 묶여 있어 순수한 기준 대조용은 아니다
- **순위 변동 미리보기** — 설정 화면에서 슬라이더를 움직이면 저장 전에 "채널C 7위→2위 ▲5"를
  보여준다. 가중치는 감으로 정할 수 없고 순위가 어떻게 흔들리는지 봐야 정할 수 있다.
  **실데이터가 쌓인 뒤에 만드는 것이 맞다** — 빈 표에서는 미리보기가 아무것도 보여주지 못한다
- **차익배율 계수 검증** — `ArbitrageRatio` 의 지수 0.85·계수 1.125 는 "구독 10만 = 기대 VSR
  0.20" 을 목표로 잡은 값이다. 실데이터로 국내 평균이 다르게 나오면 함께 조정한다

## 2. 인스타 교차 매핑 — 선행 조건 있음

**Meta 앱 심사와 발주사 인스타 비즈니스 계정 연결이 먼저다.** 그전에는 코드를 써도 검증할 수 없다.

- 채널 설명·링크에서 인스타 핸들 추출(05-INTEGRATION)
- Business Discovery 로 팔로워·최근 게시물 지표
- **개인 계정은 조회 불가** — 화면에 "조회 불가"로 표시하고 빈칸으로 두지 않는다
- 인스타 지표를 점수에 넣을지는 별도 판단 — 넣으면 인스타가 없는 채널이 부당하게 불리해진다

## 3. DM 초안 생성

- 심사에서 `PROPOSE` 로 마킹된 채널이 입력이다(`channel_review`)
- 자막·댓글에서 뽑은 구체적 근거를 넣어야 초안의 값이 있다
- **발송은 사람이 한다.** 콜드 DM 자동 발송은 명세 §제외 1(플랫폼 정책·계정 정지 위험)
- 루브릭이 안정된 뒤에 만든다 — 점수가 흔들리면 DM 대상도 흔들려 검증이 어렵다

## 4. 트렌드 외부 소스 (선택)

1차는 **우리 코퍼스**(인기 차트·검색 결과·영상 제목)로 구현되어 있고 그것으로 루프가 돈다.
외부 소스를 붙인다면 우선순위는 이렇다.

| 후보 | 판단 |
|---|---|
| **네이버 데이터랩 쇼핑인사이트** | 유일하게 권할 만하다. 공식 API·무료이고, 카테고리별 인기 검색어는 "구매하려고 검색한 말"이라 커머스 광고 소재로 직결된다 |
| 구글 트렌드 | 공식 API 가 없다. 비공식 라이브러리는 상시 깨진다 |
| 커뮤니티 스크래핑 | **하지 않는다.** ToS·상시 깨짐 문제보다 결정적인 것은 화제어에 구매 의도가 없다는 점이다. 걸러내려면 AI 를 태워야 하는데 그 비용이 얻는 것보다 크다 |
| 인스타 해시태그 | Graph API 로 가능하나 주 30개 제한. 인스타 연동을 먼저 해야 한다 |

붙일 때는 `KeywordExtractor` 처럼 인터페이스를 하나 두고 소스별 구현을 꽂는다.

## 5. 운영 준비 (배포 전 필수)

| 항목 | 내용 |
|---|---|
| **Docker 이미지에 `yt-dlp`** | 버전 고정 필요. 지금 이미지에는 없어 자막 수집이 동작하지 않는다 |
| `YOUTUBE_API_KEY` | Google Cloud Console 발급. 무료(일 10,000 units). **서버 IP 제한**을 건다 |
| `OPENAI_API_KEY` | **사용량 하드 리밋이 걸린 키만.** 이쪽만 과금된다 |
| 자막 차단 감시 | 3회 연속 `BLOCKED` 시 텔레그램 경고 — 설계에는 있으나 미구현 |
| 배치 켜기 | `influencer.batch.enabled`·`influencer.rising.weeklyNotificationEnabled` 기본 꺼짐 |

## 6. 알려진 한계 (의도적으로 남긴 것)

| 한계 | 이유 |
|---|---|
| 쇼츠 전용 인플루언서 평가 불가 | 롱폼 5개 미만은 하드 탈락. 쇼츠는 조회수 자릿수가 달라 같은 루브릭을 쓸 수 없다. 지표는 저장 중이므로 별도 루브릭 합의 후 확장 |
| 시청자 인구통계 없음 | 채널 소유자 OAuth 가 있어야 얻는다. AI 가 댓글 문체로 추정하되 `inferred` 로 표시 |
| 단가는 추정치 | 실제 견적을 화면에서 입력하면 실측으로 바뀐다. **30건쯤 쌓이면 카테고리별 계수를 발주사 데이터로 다시 잡을 수 있다** |
| 키워드 추출이 휴리스틱 | 형태소 분석기를 쓰면 정확도가 오르지만 사전 로딩 비용과 의존성이 붙는다. `KeywordExtractor` 인터페이스 뒤에서 교체 가능 |
| 다중 인스턴스 미지원 | AI 쿨다운·설정 캐시가 인스턴스별로 따로 돈다. 단 **일일 상한은 DB 라 유효**하다. 바꿀 지점은 `AiCallGuard`·`SystemConfigService` 두 곳 |

## 7. 코드 지도

```
palim-automation/influencer/
  scoring/     순수 계산 — 지표·룰70·라이징100·등급·CPV. DB 를 모른다
  domain/      엔티티 — 채널·영상·스냅샷·캠페인·분류·점수·심사
  youtube/     API 클라이언트 + 할당량 원장
  collect/     채널 등록·지표 갱신 (upsert)
  discover/    발굴 3경로 + 재개 커서
  taxonomy/    자체 카테고리 체계 (설정에서 읽음)
  transcript/  자막 어댑터 (scripts/ 호출)
  comment/     댓글 저장 (작성자 정보 없음)
  ai/          심사 오케스트레이션 · 프롬프트 · 인용 검증 · 사용량 제한
  rising/      라이징 신호 · 차익배율 · 주간 알림
  trend/       키워드 추출 · 주간 집계 · 시드 환류
  batch/       야간 배치

palim-common/config/   SystemConfig — 모든 모듈이 쓰는 런타임 설정 저장소
palim-web/influencer/  등급표 · 채널 상세 · 라이징 레이더 · 트렌드 보드 · 캠페인
palim-web/settings/    시스템 설정 화면
scripts/               youtube_transcript.py
```

**계산 규칙을 바꾸려면** `scoring/`·`rising/` 의 순수 함수와 그 단위 테스트만 보면 된다.
**기준값을 바꾸려면** 코드가 아니라 설정 화면이다.
