# 인플루언서 등급표 — 남은 작업과 재개 지침

> #41 에서 구현한 범위 밖의 항목을 정리한다. 다시 돌아와 이어 작업할 때 **왜 이렇게 남겼는지**를
> 먼저 읽고 시작한다. 설계 원본은 같은 폴더의
> `2026-08-11-influencer-grading-design.md` 와 `2026-08-11-influencer-ai-review-standard.md`.

## 지금 상태 한 줄

**정량 70점 + AI 30점이 동작하고 화면에서 심사까지 된다.** 발굴·수집·채점은 야간 배치로 돌고,
AI 심사만 수동 트리거다. 모든 기준값은 DB(`SystemConfig`)에 있어 재기동 없이 화면에서 바뀐다.

## 재개 전 반드시 알아야 할 것

| 항목 | 내용 |
|---|---|
| 기준값의 원본 | 코드가 아니라 **DB** 다. `ConfigDefinition` 은 최초 1회 기본값일 뿐이고 배포는 기존 값을 덮어쓰지 않는다 |
| 설정을 읽는 시점 | **빈 생성자·`@PostConstruct` 에서 읽으면 기동이 깨진다.** 부트스트랩이 빈 생성 뒤에 돌기 때문 — 첫 사용 시점으로 미룬다(`ConfigReader` javadoc) |
| 점수 재현성 | `influencer_score.input_hash` 가 같으면 AI 를 다시 부르지 않는다. 프롬프트·루브릭 버전도 해시에 들어간다 |
| 자막 | 공식 API 로는 남의 영상 자막을 못 받는다. yt-dlp 경로는 **언제든 깨지는 전제**이며 실패는 정상 분기다 |
| 비용 | YouTube 는 무료(할당량만), **OpenAI 만 과금**. 쿨다운+일일 상한 두 층으로 막혀 있다 |

## 1. 캘리브레이션 — 가장 먼저 할 일

**지금 루브릭 초기값은 검증된 값이 아니다.** 국내 유튜브 실측 감각에 기반한 출발점일 뿐이며,
이 상태로 등급을 대외 산출물로 쓰면 안 된다(설계 스펙 §13).

### 절차

1. 발주사가 "이 사람은 좋다 / 이 사람은 아니다"라고 아는 채널 **15~20개**를 수동 시드로 등록
   (캠페인 관리 화면 → 채널 직접 추가)
2. 캠페인을 만들고 채점 실행
3. 시스템 순위와 발주사 직관을 대조
4. 어긋나면 설정 화면에서 가중치 조정 → 재채점 → 다시 대조
5. 합의된 값이 **루브릭 문서 v1** 이 되고, `influencer.scoring.rubricVersion` 을 올린다

### 만들면 좋은 것

- **정답셋 테이블** — 채널별 발주사 평가(상/중/하)를 저장하고 시스템 순위와 나란히 보여주는 화면.
  지금은 `channel_review` 가 그 역할을 일부 하지만 캠페인에 묶여 있어 순수한 기준 대조용은 아니다
- **순위 변동 미리보기** — 설정 화면에서 슬라이더를 움직이면 저장 전에 "채널C 7위→2위 ▲5"를
  보여준다. 가중치를 감으로 정할 수 없고 순위가 어떻게 흔들리는지 봐야 정할 수 있기 때문에,
  이것이 설정 화면의 핵심 가치다. **실데이터가 쌓인 뒤에 만드는 것이 맞다** — 빈 표에서는
  미리보기가 아무것도 보여주지 못한다

## 2. 라이징 레이더 화면 + 주간 알림

지수(100점)는 **이미 계산되어 `influencer_score.rule_breakdown` 의 `rising` 에 저장 중**이고,
임계 이상이면 `RISING` 배지가 붙고 채널 티어가 `RISING`(매일 갱신)으로 올라간다. 남은 것은
보여주는 부분뿐이다.

### 필요한 것

- `rising_signal` 테이블(설계 스펙 §9) — 지금은 점수 행 안에 묻혀 있어 "라이징만 모아 보기"가
  느리다. 채널별 최신 1행 + `detected_at` + `active`
- **차익배율**을 화면 최상단에 — `조회수 중앙값 ÷ (구독자 기반 기대 조회수)`. 사장님이 실제로
  볼 숫자는 점수가 아니라 이것이다
- 감지 후 경과일 표시 — **라이징은 유통기한이 있는 정보다.** 2주 늦으면 단가가 이미 올라 있다
- 주간 텔레그램 알림 — `palim-notification` Outbox 경유(직접 봇 호출 금지). "이번 주 신규
  라이징 N명"

## 3. 트렌드 보드

외부 서비스를 붙일 필요가 없다. **우리가 매일 긁는 것 자체가 트렌드 데이터**다 — 인기 차트,
검색 결과, 신규 영상 제목·태그가 매일 수천 건 쌓인다.

- `trend_keyword` 테이블(주차 × 카테고리 × 키워드 × 빈도 × 전주 빈도)
- 주간 집계 배치 — 순수 문자열 빈도 계산이라 **AI 비용 0**
- 뜨는 키워드를 **발굴 시드로 자동 환류** — "새 트렌드 등장 → 그 키워드로 검색 → 그 분야
  라이징 발굴"이 루프로 돈다. 트렌드 민감성이라는 요구는 이 루프 자체다
- 채널 최근 영상이 뜨는 키워드와 겹치면 등급표에 `TREND` 배지 (`Badge.TREND` 는 이미 정의됨)

## 4. 인스타 교차 매핑

**선행 조건이 있다** — Meta 앱 심사와 발주사 인스타 비즈니스 계정 연결. 그전에는 코드를 써도
검증할 수 없다.

- 채널 설명·링크에서 인스타 핸들 추출(05-INTEGRATION)
- Business Discovery 로 팔로워·최근 게시물 지표
- **개인 계정은 조회 불가** — 화면에 "조회 불가"로 표시하고 빈칸으로 두지 않는다
- 인스타 지표를 점수에 넣을지는 별도 판단 — 넣으면 인스타가 없는 채널이 부당하게 불리해진다

## 5. DM 초안 생성

- 심사에서 `PROPOSE` 로 마킹된 채널이 입력이다(`channel_review`)
- 채널별 개인화 메시지 초안 — 자막·댓글에서 뽑은 구체적 근거를 넣어야 초안의 값이 있다
- **발송은 사람이 한다.** 콜드 DM 자동 발송은 명세 §제외 1(플랫폼 정책·계정 정지 위험)
- 루브릭이 안정된 뒤에 만든다 — 점수가 흔들리면 DM 대상도 흔들려 검증이 어렵다

## 6. 운영 준비 (배포 전 필수)

| 항목 | 내용 |
|---|---|
| Docker 이미지 | `yt-dlp` 설치 + 버전 고정 필요. 지금 이미지에는 없다 |
| `YOUTUBE_API_KEY` | Google Cloud Console 발급. **서버 IP 제한**을 건다 |
| `OPENAI_API_KEY` | **사용량 하드 리밋이 걸린 키만.** 이쪽만 과금된다 |
| 자막 차단 감시 | 3회 연속 `BLOCKED` 시 텔레그램 경고 — 설계에는 있으나 미구현 |
| 발굴 배치 켜기 | `influencer.batch.enabled` 기본 꺼짐. 시드 키워드 확정 후 켠다 |

## 7. 알려진 한계 (의도적으로 남긴 것)

| 한계 | 이유 |
|---|---|
| 쇼츠 전용 인플루언서 평가 불가 | 롱폼 5개 미만은 하드 탈락. 쇼츠는 조회수 자릿수가 달라 같은 루브릭을 쓸 수 없다. 쇼츠 지표는 저장만 하고 있으므로 별도 루브릭 합의 후 확장 |
| 시청자 인구통계 없음 | 채널 소유자 OAuth 가 있어야 얻는다. AI 가 댓글 문체로 추정하되 `inferred` 로 표시 |
| 단가는 추정치 | 실제 견적을 화면에서 입력하면 실측으로 바뀐다. **30건쯤 쌓이면 카테고리별 계수를 발주사 데이터로 다시 잡을 수 있다** — 남의 추정치를 긁어오는 것보다 정확하다 |
| 외부 랭킹 사이트 크롤링 안 함 | 리스크는 크고 얻는 것은 우리가 이미 계산 중인 값과 겹친다. 판단 근거는 대화 기록과 설계 스펙 §3 |
| 다중 인스턴스 미지원 | AI 쿨다운이 인스턴스별로 따로 돈다. 단 **일일 상한은 DB 라 유효**하다. 바꿀 지점은 `AiCallGuard` 한 곳 |

## 8. 코드 지도 (어디에 무엇이 있나)

```
palim-automation/influencer/
  scoring/     순수 계산 — 지표·룰70·라이징100·등급·CPV. DB 를 모른다
  domain/      엔티티 — 채널·영상·스냅샷·캠페인·분류·점수·심사
  youtube/     API 클라이언트 + 할당량 원장
  collect/     채널 등록·지표 갱신 (upsert)
  discover/    발굴 3경로 + 재개 커서
  taxonomy/    자체 카테고리 체계 (설정에서 읽음)
  transcript/  자막 어댑터 (scripts/ 호출)
  comment/     댓글 저장 (작성자 정보 없음)
  ai/          심사 오케스트레이션 · 프롬프트 · 인용 검증 · 사용량 제한
  batch/       야간 배치

palim-common/config/   SystemConfig — 모든 모듈이 쓰는 런타임 설정 저장소
palim-web/influencer/  등급표·채널 상세·심사 화면
palim-web/settings/    시스템 설정 화면
scripts/               youtube_transcript.py
```

**계산 규칙을 바꾸려면** `scoring/` 의 순수 함수와 그 단위 테스트만 보면 된다.
**기준값을 바꾸려면** 코드가 아니라 설정 화면이다.
