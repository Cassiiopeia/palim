# 재고 맞추기 — 화면 구조와 끊긴 길

> 이 문서가 다루는 것: 사장님이 재고 대조를 쓰기까지 걷는 길 전체. 메뉴 구조, 원천을 붙이는
> 흐름, 품목을 잇는 화면, 그리고 **그 길이 지금 끊겨 있는 지점들**.
>
> 대조 엔진의 판단 규칙(확정된 연결만 합산·기준 시각이 다르면 거부·관찰중→확정 승격)은
> 그대로 둔다.

## 왜 다시 짜는가

처음에는 「화면이 못생겼다」는 문제로 보였다. 코드를 열어 보니 그보다 깊었다.

**아직 한 번도 끝까지 가본 적이 없다.** 운영 DB 를 확인한 결과가 그 증거다.

```
   커넥터 1개 (이카운트, 테스트 키로 연결만 확인)   칸 맞추기 미확정
   실행 이력 0회        수집된 재고 0건        ONEWMS 연결 안 됨
```

화면 하나하나는 동작한다. 그런데 **이어지지 않는다.** 세 군데가 끊겨 있다.

| 끊긴 곳 | 무슨 일이 일어나는가 |
|---|---|
| ONEWMS 를 붙일 수 없다 | 연결 검증은 성공하는데 저장이 안 되고, 다음에 뭘 할지 안내도 안 뜬다 |
| LIVE 를 돌리면 전 행이 실패한다 | `source` 가 필수인데 그것을 채우는 코드가 어디에도 없다 |
| 대조가 영원히 안 돈다 | 대조 정의를 만드는 화면도 시드도 없어 `reconcile_definition` 이 0행이다 |

그래서 이 문서는 화면 구조와 끊긴 길을 **같이** 다룬다. 배관만 고치면 그것을 조작할 자리가
없고, 화면만 그리면 예쁜 막다른 길이 된다.

## 전체 그림

```
   ①연결        ②칸 맞추기         ③품목 맞추기            ④대조
   ─────────    ─────────────      ────────────────       ──────────
   이카운트  →  받아온 칸을 보고  →  하나씩 확인 (큐)    →  매일 아침
   ONEWMS       표준 칸에 배치       ↕                      자동 실행
   (+ 새 원천)   품명 필수            전체 표로 확인
                                     언제든 고치기
```

각 단계가 다음 단계에 필요한 것을 만들어 넘긴다. ①이 받아온 칸을 보여주고, ②가 그것을 표준으로
옮기고(품명 포함), ③이 품명으로 잇고, ④가 그 위에서 돈다.

**①②는 한 호흡이다.** 새 원천을 붙일 때 연결만 하고 멈추면 데이터가 한 줄도 안 들어오므로,
받아온 칸을 본 김에 배치까지 끝낸다.

**나중에 손볼 때는 따로 들어간다.** 비밀번호만 바꾸고 싶은데 칸 맞추기까지 지나갈 이유가 없다.
두 경로를 목록 화면이 잇는다.

## 메뉴

```
   홈
   알림 이력

   [재고 맞추기]
    재고 가져오는 곳
    품목 맞추기
    대조 결과

   [인플루언서]
    등급표 · 라이징 레이더 · 트렌드 보드 · 캠페인 관리

   [설정]
    알림 · 시스템 · 계정
    ▸ 고급 (표준 표 · 감사 로그)
```

「재고 맞추기」 세 항목이 여정 순서 그대로다. **원천이 몇 개로 늘어나도 메뉴는 안 늘어난다** —
「재고 가져오는 곳」 안에서 행이 늘 뿐이다.

| 없앤다 | 어디로 | 왜 |
|---|---|---|
| 시작하기 | 홈이 흡수 | 순서 안내가 순서 밖에 있으면 안 된다 |
| 외부 시스템 연결 | 목록의 버튼 | 목록이 있으면 거기서 추가한다. 둘 다 메뉴에 있으니 차이를 알 수 없다 |
| 목표 모델 | 설정 > 고급 | 사장님이 볼 일 없는 내부 개념이다 |
| 단위 환산 | **시스템별 상세** | 아래에 이유를 적는다. 품목 맞추기가 아니다 |

| 지금 이름 | 바꾼 이름 |
|---|---|
| 연동 커넥터 | 재고 가져오는 곳 |
| 맞춰 보기 | 대조 결과 |
| 품목 잇기 | 품목 맞추기 |

**주소는 유지한다.** `/connectors`, `/connectors/connect`, `/connectors/units` 를 그대로 두고
메뉴에서만 빼거나 옮긴다. 주소를 바꾸면 백링크·리다이렉트·테스트를 함께 고쳐야 하는데, 얻는
것이 없다.

# 화면별 설계

각 화면마다 **그 화면이 뚫어야 할 길**을 함께 적는다.

## 홈 — 시간에 따라 다른 것을 보여준다

```
 ┌─ 아직 준비 중 ───────────────────────────┐  ┌─ 다 붙인 뒤 ─────────────────────────┐
 │  재고를 맞춰 보려면 두 가지가 필요합니다   │  │  오늘 아침 맞춰 봤습니다   06:30      │
 │                                          │  │                                      │
 │  ●━━━━━━━━━●━━━━━━━━━○━━━━━━━━○         │  │   확인할 것 2건   지켜볼 것 5건       │
 │   가져오는 곳  품목 맞추기   대조          │  │   아직 안 이어진 품목 37건            │
 │      1/2         아직         아직        │  │   ┌────────────────────────────┐    │
 │                                          │  │   │ 제품A 227g  전산 9,451     │    │
 │  ▸ 지금 할 일                             │  │   │             실물 9,000     │    │
 │    ONEWMS 를 붙이면 비교할 짝이 생깁니다   │  │   │             451 차이 ▲     │    │
 │    [ ONEWMS 붙이기 ]                      │  │   └────────────────────────────┘    │
 └──────────────────────────────────────────┘  └──────────────────────────────────────┘
```

준비가 안 끝났으면 **다음 한 걸음만** 보여준다. 여러 개를 나열하면 무엇부터 할지 다시 고민하게
된다. 끝났으면 **오늘 결과**를 보여준다 — 매일 여는 화면이 되어야 하기 때문이다.

**여기서 뚫어야 할 것**

- 홈에는 흡수할 코드가 한 줄도 없다. `HomeController` 는 `SetupService` 를 주입조차 하지 않고,
  템플릿은 재고와 무관한 3단계(텔레그램·자동화 모듈·알림 이력)를 하드코딩하고 있다. 주입 +
  모델 + `setup/index.html` 의 카드 렌더링 이식이 전부 필요하다
- **`SetupService` 의 2·3·4단계가 「준비 중」으로 굳어 있다.** 품목 맞추기·대조·자동 실행은 이미
  있는데도 그렇게 말한다. 지금은 잘 안 보이는 화면이라 티가 안 났지만, 홈으로 올라오면 첫
  화면이 매일 거짓말을 한다. 실제 상태로 계산하게 고친다
- 1단계 판정이 「연결됨」만 본다. 그런데 **칸을 맞추지 않으면 수집이 돌지 않는다**(스케줄러가
  ACTIVE 매핑을 요구한다). 연결 2개만으로 DONE 을 주면 데이터가 안 들어오는데 홈은 다 됐다고
  한다. 매핑 확정 여부를 함께 봐야 한다
- 4단계 판정이 `scheduleCron != null` 하나뿐이라 스케줄러의 실제 조건과 어긋난다. cron 만 넣고
  매핑을 확정하지 않은 커넥터에 「예약되어 있습니다」라고 말하지만 스케줄러는 영원히 건너뛴다
- 「지켜볼 것」을 셀 때 **미매칭을 빼야 한다.** 미매칭도 `OBSERVING` 으로 저장되기 때문에
  상태만 보고 세면 「재고를 맞출 일」과 「품목을 이을 일」이 한 숫자에 섞인다. 둘은 할 일이
  다르므로 따로 센다

## 재고 가져오는 곳 — 두 문을 잇는 자리

```
 ┌─ 재고 가져오는 곳 ───────────────────────────── [ + 시스템 붙이기 ] ─┐
 │   시스템          연결    칸 맞추기   자동 수집    마지막            │
 │  ─────────────────────────────────────────────────────────────────  │
 │   이카운트 ERP     ✔      ✔ 5칸      매일 06:00   오늘 1,204건  ›   │
 │   ONEWMS          ✔      ⚠ 안 함    —            —             ›   │
 └─────────────────────────────────────────────────────────────────────┘
```

「연결」과 「칸 맞추기」가 **한 행에 나란히** 있다. 연결만 하면 끝난 것처럼 보이던 문제가 여기서
사라진다. ⚠ 가 곧 할 일이다.

**여기서 뚫어야 할 것**

- 목록 한 줄에 연결 상태도 자동 수집도 없다(`ConnectorSummary` 와 조회 SQL 양쪽에 빠져 있다).
  홈이 「손봐야 할 게 있다」고 보내도 어느 줄이 문제인지 알 수 없다. 두 칸을 추가한다
- 생성 경로가 둘이다. 목록의 [새 연동 만들기]는 `/connectors/new` 로 가는데 그 화면은 코드·목표
  모델·원천 타입을 사람에게 직접 묻는 옛 폼이고, `/connectors/connect` 는 검증 후 그 값들을 대신
  정해 준다. **[+ 시스템 붙이기]가 `/connectors/connect` 를 가리키게 하고, 옛 폼은 고급으로
  내린다.** 어느 문으로 들어왔는지에 따라 난이도가 완전히 달라지는 상태를 없앤다

## 시스템별 상세 — 지금 없는 화면

```
 ┌─ 이카운트 ERP ──────────────────────────────────────────────────────┐
 │   연결        ✔ 정상        마지막 확인 08-14 06:00   [ 고치기 ]     │
 │   칸 맞추기   ✔ 5칸 · 품명 있음                       [ 다시 맞추기 ]│
 │   자동 수집   매일 06:00                              [ 시각 바꾸기 ]│
 │   단위 환산   BOX → EA  ×12                           [ 규칙 관리 ]  │
 │   실행 이력   오늘 1,204건 성공                       [ 이력 보기 ]  │
 │                                              [ 이 시스템 떼어내기 ]  │
 └─────────────────────────────────────────────────────────────────────┘
```

한 시스템의 상태가 한 자리에 모인다. 「이카운트 연결만 확인하고 싶다」가 갈 곳이 생긴다.

**여기서 뚫어야 할 것**

- `GET /connectors/{id}` 자체가 없다. 컨트롤러와 템플릿을 새로 만든다
- **자동 수집 시각을 넣는 UI 가 어디에도 없다.** `scheduleCron` 을 저장하는 경로가 전무해서
  자동 수집은 영원히 0건이고 홈의 4단계는 절대 완료되지 않는다. 이 화면이 그 자리다
- **단위 환산이 여기로 온다.** 처음에는 품목 맞추기로 흡수하려 했는데 불가능하다 —
  환산 규칙이 없어 막힌 행은 `std_stock_snapshot` 에 들어오지 못하고, 품목 맞추기의 후보는
  그 테이블에서 나온다. **환산이 필요한 바로 그 품목이 품목 맞추기 화면에 나타나지 않는다.**
  게다가 두 값은 다르다 — 「단위 환산」은 적재할 때 원천 단위를 기준 단위로 바꾸는 것이고,
  품목 맞추기의 배수(`×12`)는 대조할 때 쓰는 값이다. 적재 단계의 문제는 적재 단계 화면에서 푼다
- 실행 결과 화면에서 「단위 때문에 막혔다」가 보일 때 **여기로 오는 링크**를 건다. 지금은 실패를
  본 화면에서 해결 화면으로 갈 방법이 없어 사이드바에서 스스로 찾아야 한다
- 자격증명을 다시 넣는 경로가 없다(저장 서비스가 생성 전용이고 같은 코드면 거부한다). 인증키가
  만료되면 고칠 방법이 없다. [고치기]가 이것을 한다

## 연결 화면 — 읽을 것보다 채울 것을 먼저

실제로 채우는 칸은 3개인데 설명이 그 3개를 두 번 덮고 있다. 화면을 열면 발급 방법이 펼쳐진
채라 입력칸이 첫 화면에 아예 안 보인다.

```
 ┌────────────────────────────────┐
 │ 시스템 붙이기 · 2/3            │   ← 전체 여정의 어디인지
 │ 이카운트 ✔  ONEWMS ← 지금      │
 │                                │
 │ 어떤 시스템   [ 이카운트  ▾ ]  │
 │ 회사코드     [          ]      │
 │ 사용자 ID    [          ]      │
 │ 인증키       [          ]      │
 │                                │
 │        [ 연결 확인하기 ]        │
 │                                │
 │ ▸ 인증키 어디서 받나요?         │   ← 접어 둔다
 │ ▸ 접속 주소 직접 지정           │
 └────────────────────────────────┘
```

성공하면 **받아온 칸을 맨 위에** 보여준다. 이것이 다음 단계의 재료이고, ONEWMS 처럼 응답 스펙을
모르는 원천을 붙이는 **유일한 방법**이기 때문이다. 새 원천이 3번째, 4번째로 와도 똑같다 —
미리 아는 것이 아니라 **받아 보고 맞추는** 구조다.

```
 ┌─ 연결됐습니다 ────────────────────────────────────────────────┐
 │  지역 조회 ✔ 320ms   로그인 ✔ 610ms   재고 조회 ✔ 1건 880ms   │
 │                                                              │
 │  받아온 칸    WH_CD    PROD_CD    PROD_DES    BAL_QTY         │
 │  │  200      A0001     제품A 227g   9451           │          │
 │                                                              │
 │  ⓘ 방금 쓰신 테스트 인증키는 이 조회에 성공하면서 만료됐습니다.│
 │     이카운트가 그렇게 정해 둔 것이라 정상입니다.               │
 │     [ 정식 인증키 받는 법 ]   [ 정식 키 넣고 저장하기 ]        │
 └──────────────────────────────────────────────────────────────┘
```

**「테스트 인증키 / 정식 인증키」 라디오를 없앤다.** 처음 오는 사람은 고를 것이 없다 — 무조건
테스트 키부터다. 고를 수 없는 것을 물어보느라 8줄을 쓰고 있었다.

**여기서 뚫어야 할 것 — 이 화면이 가장 많이 막혀 있다**

- **라디오는 표시용이 아니라 저장 스위치다.** 「정식 키」일 때만 저장 로직이 돈다. 그냥 지우면
  어떤 커넥터도 저장되지 않고, 설정에 「테스트」가 박힌 채 매일 테스트 주소를 부르게 된다.
  **지우기 전에 「정식 키를 넣고 저장한다」는 별도 경로를 먼저 만든다.** 위 그림의
  [정식 키 넣고 저장하기]가 그것이다
- **ONEWMS 는 지금 연결을 끝까지 마칠 수 없다.** 이카운트가 아닌 원천은 라디오가 화면에서
  숨겨지는데 값은 「테스트」로 전송된다. 결과: 검증 성공 → 저장 안 됨 → 「정식 키 받으세요」
  안내도 안 뜸. **성공했는데 아무 일도 일어나지 않는다.** 키 단계가 없는 원천은 검증 즉시
  저장으로 가야 한다
- **연결 성공 안내가 화면에 안 뜬다.** 안내를 `message` 라는 이름으로 담는데 레이아웃은
  `flashSuccess` 를 읽는다. 「이제 어떤 항목을 어디에 담을지만 정하면 끝입니다」라는, ①에서 ②로
  넘기는 가장 중요한 문장이 통째로 사라지고 있다. 이름을 맞춘다
- 실패했을 때 이 화면으로 되돌리는 리다이렉트가 있으므로 **주소는 살려 둔다**. 메뉴에서만 뺀다

## 칸 맞추기 — 품명을 필수로

```
 ┌─ 칸 맞추기 · 이카운트 ─────────────────────────────────────────────┐
 │  ■ 없으면 저장이 안 됩니다                                   5/5 ✔ │
 │     품목 A PROD_CD   수량 A BAL_QTY   품명 A PROD_DES              │
 │     기준시각 A(자동)  출처 A(자동)                                  │
 │                                                                   │
 │  ▸ 더 담을 것 (창고·로트·유통기한·금액 …)                  0/23    │
 └───────────────────────────────────────────────────────────────────┘
```

품명 없이도 저장은 된다. 그리고 며칠 뒤 품목 맞추기에서 코드만 두 개 놓고 「이 둘이 같은
물건인가」를 판단해야 한다. 자동 후보 제안도 조용히 0건이 된다.

**필수로 올려도 막히는 원천은 없다.** 「품목」 칸은 코드가 아니라 **행을 구분할 값**이라, 코드를
주지 않는 원천은 품명을 그 자리에 넣으면 그대로 돌아간다. 품명을 아예 주지 않는 재고 시스템은
사실상 없고, 있다 해도 그 원천은 애초에 대조에 쓸 수 없다.

**지금 올려야 한다.** 수집된 데이터가 0건이라 잃을 것이 없다.

**여기서 뚫어야 할 것**

- **`source` 가 이미 필수인데 아무도 채우지 않는다.** 화면에서는 「시스템이 채웁니다」로 빠져
  있는데, 실제로 채우는 코드가 어디에도 없다. 그대로 LIVE 를 돌리면 **전 행이
  `REQUIRED_FIELD_MISSING(source)` 로 실패**하고 적재 0건 + 오류 N건이 쌓인다. 적재 시 커넥터
  코드를 주입한다. **이것이 ②와 ③ 사이의 끊긴 자리다**
- **품명 필수는 코드만 고치면 안 먹힌다.** 필드 부트스트랩이 「없는 필드만」 추가하고 기존 행을
  갱신하지 않아서, 이미 부팅한 DB(운영·CI)에서는 아무 일도 일어나지 않는다. `V21` 마이그레이션
  으로 기존 행을 갱신한다
- 필수를 올리면 **매핑을 확정할 때 막아야 한다.** 지금 확정에는 필수 충족 검사가 없어서 확정은
  통과하고 첫 실행에서 전 행이 죽는다. 화면의 `5/5 ✔` 는 표시일 뿐 게이트가 아니다
- 실패 문구가 사람 말이 아니다. 실행 결과 화면에 `REQUIRED_FIELD_MISSING(K007) args=[…]` 가
  그대로 나온다. 사람이 읽는 문구로 바꾼다

## 품목 맞추기 — 하나씩 → 전체 → 언제든 수정

### 하나씩 확인

```
 ┌─ 품목 맞추기 ─────────────────────  37개 중 1번째  ─  [ 표로 보기 ] ─┐
 │   ONEWMS 의 이 품목은 이카운트의 무엇입니까?                          │
 │   ┌─ ONEWMS ─────────────────┐    ┌─ 이카운트 ────────────────────┐ │
 │   │ 품명  제품A 227g          │    │ ◉ 제품A 227g                 │ │
 │   │ 코드  W-227               │ ←→ │   A0001 · 낱개 · 9,451개      │ │
 │   │ 단위  낱개                │    │ ○ 제품A 500g   A0007          │ │
 │   │ 수량  9,000개             │    │ ○ 직접 찾기…                  │ │
 │   │ ▸ 원본 그대로 보기        │    └───────────────────────────────┘ │
 │   └──────────────────────────┘                                      │
 │   ⓘ 이름이 거의 같고 수량도 비슷합니다 (451 차이)                     │
 │                      [ 아니오, 나중에 ]   [ 맞습니다 · 다음 → ]      │
 └─────────────────────────────────────────────────────────────────────┘
```

**양쪽이 실제로 보낸 값을 나란히 놓는다.** 이름만으로 애매할 때가 있어서 단위·수량까지 같이
본다. 수량 비교가 특히 쓸모 있다 — 이름이 비슷해도 수량이 100배 차이 나면 다른 물건이다.

**「원본 그대로 보기」** 를 누르면 그 원천이 보낸 값이 전부 나온다. 매핑하지 않은 칸까지다.
매핑하지 않은 칸은 버려지지 않고 원본 그대로 남아 있어서, 원천이 무엇을 보내는지 미리 알
필요가 없다.

### 전체 표

```
 ┌─ 품목 맞추기 ────────  맞춘 것 1,167  ·  안 맞춘 것 0  ─  [ 하나씩 보기 ] ─┐
 │  [ 전체 ▾ ]  [ 검색                    ]                                  │
 │   제품              단위    이카운트            ONEWMS           (+원천)  │
 │   제품A 227g        EA      A0001 제품A 227g    W-227 제품A 227g    —     │
 │   제품C 1박스=12개  EA      A0003 제품C         W-C12 제품C(박스) ×12     │
 └──────────────────────────────────────────────────────────────────────────┘
```

**행이 제품, 열이 원천이다.** 원천이 늘면 열이 늘 뿐 구조는 그대로다.

### 언제든 수정

```
 │   ┌────────────────────────────────────────────────────────────────┐    │
 │   │  이카운트  A0001  제품A 227g   ×1     확인함 08-14   [ 떼기 ]  │    │
 │   │  ONEWMS   W-227  제품A 227g   ×12    확인함 08-14   [ 떼기 ]  │    │
 │   │                                          [ + 다른 원천 잇기 ]  │    │
 │   │  ⚠ 떼면 오늘부터 이 품목은 대조에서 빠집니다.                   │    │
 │   │     지난 대조 결과는 그대로 남습니다.                           │    │
 │   └────────────────────────────────────────────────────────────────┘    │
```

**떼면 어떻게 되는지 그 자리에서 말한다.** 잘못 이어둔 것을 고칠 때 가장 걸리는 것이 「지난
기록도 날아가나」인데, 안 날아간다.

**여기서 뚫어야 할 것 — 이 화면이 가장 많이 비어 있다**

- 지금은 세 섹션짜리 단일 화면이고 큐·전체표·수정에 해당하는 조회·명령이 **하나도 없다**
- **후보 찾기가 「이름이 정확히 같은 것」만 묶는다.** 유사도 점수도, 차순위 후보도, 검색도 없다.
  위 그림의 「◉ / ○ / ○ 직접 찾기」와 「이름이 거의 같고 수량도 비슷합니다」는 **그 계산을
  새로 만들어야** 나온다. 이 화면에서 가장 큰 작업이다
- **배수(`×12`)를 넣을 자리가 없다.** 제안할 때 배수가 1 로 고정되어 있고 폼에 입력칸이 없다
- 「언제든 수정」에 필요한 도메인 메서드(배수 변경·이름 변경·비활성)는 있지만 **전부 호출자가
  0인 죽은 코드**다. 서비스 명령·엔드포인트·화면이 통째로 없다. 「기존 코드가 있으니 화면만
  붙이면 된다」가 아니다
- 후보 목록에 **확정한 것이 계속 다시 나온다**(제안만 된 것을 걸러내지 않는다). 큐 모드에서는
  매 건 충돌한다
- 전체 표를 지금 서비스로 그리면 **단위 수만큼 쿼리가 나가고**(N+1) 품명·수량은 아예 못 채운다.
  결합 조회를 새로 만든다
- 「원본 그대로 보기」에 필요한 값은 지금 조회 대상에 없다. 집계 방식을 바꿔야 붙는다

## 대조 결과

**여기서 뚫어야 할 것**

- **대조 정의를 만드는 화면도 시드도 없다.** 운영 DB 의 정의는 0행이고, 그래서 대조 결과는 항상
  빈 화면이며 스케줄러는 매일 아침 빈 목록을 돈다. 홈의 「오늘 결과」도 나올 수가 없다.
  **어느 원천과 어느 원천을 무엇으로 비교할지 정하는 화면**이 필요하다
- 정의는 **두 원천을 한 쌍으로** 묶는다. 원천이 셋이 되면 정의가 늘어난다(전산↔물류A,
  전산↔물류B). 대조는 본래 「두 값을 견주는」 일이라 쌍이 자연스럽고, 지금 모델도 그렇게 되어
  있다. 「행=제품, 열=원천」 표는 잇는 화면이고, 견주는 것은 쌍 단위다

# 원천이 늘어날 때

「나중에 원천이 더 생겨도 되게」가 이 설계의 전제다. 확인해 보니 **세 번째 원천부터 막힌다.**
화면이 아니라 그 아래가 막혀 있어서, 화면만 고쳐서는 풀리지 않는다.

**① 세 번째 원천은 저장이 안 된다.** 커넥터 코드를 「프리셋 + 목표 모델」로만 만든다. 그래서
같은 프리셋을 두 번 쓰면(창고 두 곳, ERP 두 곳, 직접 설정 두 개) 코드가 그대로 충돌해
「이미 쓰는 코드입니다」로 거부된다. 프리셋은 셋뿐이고, 새 원천을 붙이는 가장 흔한 방법이
「직접 설정」인데 **두 번째 「직접 설정」부터 불가능하다.** 이름이 겹치면 사람이 구분할 이름을
붙일 수 있게 해야 한다.

**② 원천이 셋이면 없는 차이가 생긴다.** 대조는 두 원천을 한 쌍으로 견준다. A 와 C 에만 있는
품목으로 만든 정합 단위는 A↔B 대조에서 「A 에만 있다」로 잡혀 **차이로 올라오고 임계를 넘으면
알림까지 간다.** 실제로는 아무 문제가 없는데도 그렇다. 정의마다 「이 쌍에 속한 품목만」 본다는
조건이 필요하다.

**③ 세 번째 원천의 품목은 잇는 화면에 나타나지 않는다.** 후보 찾기가 활성 정의 중 **첫 번째
하나만** 보고, 좌우 두 원천으로 고정되어 있다. 「전체 표는 열만 늘면 된다」가 성립하려면 후보
찾기를 쌍이 아니라 **원천 목록** 기준으로 바꿔야 한다.

**④ 한 원천이 늦으면 그 원천이 낀 대조가 전부 멈춘다.** 두 원천의 기준 시각이 어긋나면 비교를
거부하는데(이 판단 자체는 옳다), 원천이 늘수록 전부 일치할 확률이 급격히 낮아진다. 게다가 그
실패는 **조용하다** — 기록만 남고 알림이 없다. 며칠 뒤 「왜 결과가 없지」로 알게 된다.

**⑤ 어느 연동이 어떤 이름으로 저장되는지 화면에 없다.** 대조 정의는 원천 이름을 자유 문자열로
받는데, 커넥터 화면 어디에도 「이 연동은 이 이름으로 들어갑니다」가 표시되지 않는다. 원천이
늘수록 사람이 이름을 외워야 하고 오타를 잡을 방법이 없다.

**⑥ 단위 환산 규칙에 원천 구분이 없다.** 「전산의 1박스는 12개, 물류의 1박스는 10개」를 표현할
수 없다. 원천이 늘수록 전역 규칙 하나가 엉뚱한 시스템에 적용된다.

①②③ 은 원천을 셋으로 늘리기 전에 반드시 풀어야 한다. ④⑤⑥ 은 늘린 뒤에 겪는 문제라 순서를
뒤로 둘 수 있다.

# 그 밖에 끊긴 곳

화면 설계와 직접 엮이지 않지만 같이 고쳐야 이 길이 완성되는 것들.

- **연결 화면에서 나가는 길이 없다.** 취소도, 목록으로 돌아가기도 없다. 지금은 사이드바가
  유일한 출구인데 메뉴에서 빼면 **들어가면 못 나오는 화면**이 된다. 단위 환산 화면도 마찬가지다
- **연결이 끊겨도 아무도 알려주지 않는다.** 수집이 실패해도 연결 상태를 「고장」으로 바꾸는
  코드가 운영 경로에 없다. 그래서 「손봐야 한다」는 신호 자체가 발생하지 않는다
- **품목 맞추기에서 대조로 돌아가는 길이 없다.** 품목을 다 이은 뒤 「이제 맞춰 보기」로 갈 수
  없다. 반대 방향(대조 → 연결)만 있다
- **대조 알림 임계를 정하는 화면이 없다.** 임계가 비어 있으면 아무것도 알리지 않는데, 그 값을
  넣을 자리가 어디에도 없다. 알림 설정 화면은 동결 도메인 항목만 담고 있다
- **엑셀·CSV 원천은 새 연결 화면으로 만들 수 없다.** 그 경로는 API 연동으로 고정되어 있다.
  옛 폼이 유일한 파일 원천 생성 경로이므로 고급으로 내리되 없애지는 않는다
- **오래된 실행 상세가 빈 화면으로 열린다.** 최근 30건만 조회해 찾고 없으면 빈 값을 넣는다
- **테넌트를 읽는 방법이 두 갈래다.** 커넥터 쪽은 상수, 대조 쪽은 컨텍스트를 쓴다. 한 화면이
  둘을 같이 읽는 순간 어긋난다
- **재고 대조를 최상위 메뉴 그룹으로 올리는 것**은 2026-08 피벗(07-DECISIONS 023)에서 동결한
  재고 도메인과 이름이 겹친다. 동결한 것은 옛 재고 관리이고 이번 것은 새 대조 모듈이라 실제
  충돌은 아니지만, **`docs/07-DECISIONS.md` 에 항목을 추가**해 구분을 남긴다

# 구현 순서

**화면 단위로 간다.** 화면 하나를 끝낼 때마다 길이 한 칸씩 이어지고, 그 시점에 실제로 눌러 볼
수 있다.

| 순서 | 화면 | 끝나면 가능해지는 것 |
|---|---|---|
| 1 | 메뉴 · 홈 | 어디부터 해야 하는지 보인다. 「준비 중」 거짓말이 사라진다 |
| 2 | 재고 가져오는 곳 · 시스템별 상세 | 붙인 것을 한눈에 보고 따로 고칠 수 있다. 자동 수집 시각·단위 환산이 갈 자리가 생긴다 |
| 3 | 연결 화면 | **ONEWMS 를 붙일 수 있게 된다.** 원천 이름을 사람이 정할 수 있어 세 번째 원천도 막히지 않는다 |
| 4 | 칸 맞추기 | **LIVE 가 실제로 돈다**(source 주입·품명 필수) |
| 5 | 대조 정의 | **대조가 돌기 시작한다.** 알림 임계도 여기서 정한다 |
| 6 | 품목 맞추기 | 품목을 편하게 잇는다. 후보 찾기를 쌍이 아니라 원천 목록 기준으로 바꾼다 |

3~5 를 마치면 이카운트와 ONEWMS 를 실제로 붙여 대조가 한 번 돈다. 6 은 그 위에서 편의를 올리는
일이라 마지막이다.

각 단계마다 **화면을 여는 테스트를 함께 둔다.** 자료가 없는 상태와 있는 상태 양쪽으로 연다 —
목록이 비면 행을 그리는 부분이 한 번도 실행되지 않아 검사되지 않기 때문이다.
