# 후처리 스크립트 — 설계

> 원천에서 받은 값을 **담기 전에** 사장님이 직접 다듬을 수 있게 한다.

## 왜 필요한가

두 시스템의 품목코드 체계가 완전히 다르다. 이을 실마리는 **이름뿐**이다.

```
   이카운트  C16P_26.11.07   클래식 16g (26.11.07)
   물류      01013           클래식 16g (26.11.07)
```

지금 규칙(정규식 4개)으로 계산해 보면 **14종 중 11종이 이미 붙는다.** 안 붙는 것은 둘뿐이다.

```
   초콜릿 프로틴바 70g_26.12.12  →  초콜릿프로틴바70g
   초콜렛 프로틴바               →  초콜렛프로틴바      ✗  표기 + 규격
   카라멜 프로틴바 70g_26.12.09  →  카라멜프로틴바70g
   카라멜 프로틴바               →  카라멜프로틴바       ✗  규격
```

**규칙으로 다 풀려고 하면 오히려 위험하다.** `70g` 을 일괄로 빼면 클래식 16g·227g·425g·680g·850g
다섯 종이 하나로 뭉개진다. 어느 규칙이 어디까지 영향을 주는지는 **자료를 보면서 사람이 판단**해야
한다.

그래서 규칙 편집기를 만들지 않는다. **스크립트 하나**로 두고 사장님이 고친다.

## 어디에 끼우는가

```
   원천에서 받기 → 매핑 → [스크립트] → 필수 검사 → 담기
                            ↑ 여기
```

**적재 「직후」가 아니라 「직전」이다.** 이유 셋.

**하나.** 품목 맞추기가 대조보다 앞에 있다. 대조 시점에 다듬으면 품목 맞추기는 여전히 지저분한
이름을 본다. 그렇다고 양쪽에서 다듬으면 **판단이 두 군데로 갈려 언젠가 어긋난다**(07-DECISIONS
030·032 에서 이미 두 번 겪었다).

**둘.** 시험 실행이 그대로 스크립트 시험이 된다. 「담길 모습」 표가 이미 있으므로 시험 화면을
따로 만들지 않는다.

**셋.** 표준 표에는 최종값만 들어간다. 담고 나서 고치면 「담긴 값」과 「보이는 값」이 한동안
달라진다.

## 무엇을 바꿀 수 있는가 — 전부

**칸을 제한하지 않는다.** 확장성이 우선이고, 무엇을 잠글지는 코드가 정할 일이 아니다.

안전은 **막는 것이 아니라 드러내는 것**으로 확보한다.

```
   스크립트가 item_ref 를 지움
        ↓  필수 검사에 걸림
   그 줄만 「담지 못한 줄」 로 떨어지고 이유가 남음  →  진짜 표는 멀쩡
```

이 검사는 **이미 있다.** 다만 지금은 매핑 안에서 끝나므로 **스크립트 뒤로 옮긴다.** 그 이동이
이 설계의 핵심이다.

**돌려주지 않은 칸은 매핑 결과 그대로** 간다. 이름만 다듬는 스크립트를 짜도 나머지가 날아가지
않는다.

## 계약 — 스크립트는 DB 를 모른다

```
   자바가 행을 읽어 stdin 으로 넘김 → 스크립트는 계산만 → stdout 으로 돌려줌 → 자바가 반영
```

스크립트가 아무리 잘못 짜여도 **자료를 직접 망가뜨릴 수 없다.** 지우거나 다른 표를 건드리거나
트랜잭션을 물고 늘어질 방법이 없다.

그리고 **표 이름을 모르므로 시험/실제가 갈리지 않는다.** 어느 표에 담을지는 자바가 안다.
SQL 로 하면 쿼리 안에 표 이름이 들어가 시험용과 실제용이 따로 생기고, 그 둘이 어긋난다.

```python
# stdin  {"rows": [{"_row": 1, "item_ref": "...", "raw_item_name": "...", ...}, ...]}
# stdout {"rows": [{"_row": 1, "normalized_name": "..."}, ...]}
#
# - _row 는 어느 행인지 알려주는 손잡이. 우리가 붙였다 떼는 값이라 그대로 돌려주기만 하면 된다
# - 품목코드로 맞추지 않는 이유는 그러면 그 칸만은 못 바꾸기 때문이다. 모든 칸이 열려 있어야 한다
# - 바꿀 칸만 담아 돌려준다. 안 담은 칸은 매핑 결과 그대로
# - 사람에게 할 말은 stderr 로. stdout 에는 JSON 만
```

py 호출 규약은 CLAUDE.md §4 를 따른다 — 인자 배열·`PYTHONIOENCODING=utf-8`·`waitFor` 타임아웃
+ `destroyForcibly()`·전용 스레드풀(크기 2).

## 저장

```sql
create table connector_post_script (
    id            uuid         primary key,
    tenant_id     uuid         not null,
    connector_id  uuid         not null,
    name          varchar(100) not null,
    body          text         not null,
    sort_order    int          not null,
    version       int          not null,
    status        varchar(20)  not null,   -- DRAFT / ACTIVE / ARCHIVED
    is_enabled    boolean      not null,
    timeout_ms    int          not null,
    created_at    timestamptz  not null,
    updated_at    timestamptz  not null
);

create table connector_post_script_run (
    id               uuid        primary key,
    tenant_id        uuid        not null,
    script_id        uuid        not null,
    script_version   int         not null,
    connector_run_id uuid,
    status           varchar(20) not null,   -- SUCCEEDED / FAILED / TIMEOUT
    total_count      int         not null,
    changed_count    int         not null,
    stderr_tail      text,
    error_summary    text,
    started_at       timestamptz not null,
    finished_at      timestamptz
);
```

**실행 기록을 남기는 이유** — 스크립트가 조용히 실패하면 이름만 안 다듬어진 채로 대조가 계속
돈다. 「어제는 69건 바뀌었는데 오늘 0건」 을 알아채려면 숫자가 남아야 한다.

**「무엇이 바뀌었는지」 를 칸별로 보여주는 장치는 만들지 않는다.** 시험 실행의 「담길 모습」 표가
이미 결과를 보여준다. 바뀐 건수 하나면 충분하다.

## 화면

```
┌─ 후처리 스크립트 ───────────────── 연동: ONEWMS 재고 ──┐
│  ⠿  1  이름 다듬기         [✓]   v3   [고치기] [지우기] │
│  ⠿  2  바코드 앞자리 떼기   [✓]   v1   [고치기] [지우기] │
│  ⠿  3  창고코드 통일        [ ]   v2   [고치기] [지우기] │
│  [+ 스크립트 추가]                                      │
└────────────────────────────────────────────────────────┘
```

위에서부터 차례로 돌고, 앞 결과를 다음이 이어받는다. **체크를 끄면 건너뛴다** — 지우지 않고
꺼두면 「이게 문제인가」를 하나씩 꺼보며 찾을 수 있다.

**드래그앤드롭은 `/js` 아래 정적 파일로 만든다.** 화면에 박은 코드는 보안 정책에 막혀 돌지
않는다(07-DECISIONS 031). 스크립트가 막혀도 순서를 바꿀 수 있도록 **▲▼ 버튼을 함께 두고**,
스크립트가 살아 있으면 숨긴다.

편집 화면에는 **계약 표가 늘 보인다**. 파이썬을 모르는 사람이 외울 것이 없어야 한다.
자주 쓰는 처리는 **예제 서랍**에서 눌러 넣는다 — 앞뒤 공백·괄호 빼기·날짜 빼기·표기 통일·
띄어쓰기 제거·규격 떼기(⚠ 위험 표시)·칸 합치기.

시험 실행에 **「후처리 스크립트 없이 돌리기」** 체크를 둔다. 스크립트를 거치기 전 모습과
대볼 수 있어야 한다.

## 실패하면

스크립트가 죽거나 시간을 넘기면 **그 실행 전체를 실패로 남긴다.** 담기 전에 도는 것이므로
어중간하게 담기는 일은 없다. 사유는 실행 기록과 로그에 남고, 화면에는 사람 말로 나온다.

## 정하지 않은 것

- **기능 자체를 기본 꺼짐으로 둘지.** 이 저장소는 공개고 남이 가져다 쓴다. 서버에서 임의
  코드가 도는 구조이므로 설정으로 켜야 쓰이게 하는 편이 맞아 보이나, 확정하지 않았다.
- 스크립트가 쓸 수 있는 파이썬 라이브러리 범위. 지금은 표준 라이브러리만 가정한다.
